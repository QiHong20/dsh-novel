# 指定文风写作优化规划

## 一、目标与审查范围

让 AI 通过插件写小说时，不仅能模仿句长与标点节奏，还能稳定遵循指定的叙述视角、叙述距离、人物声口和表达习惯，同时保留剧情事实与章节完整性。

本规划基于 2026-11-16 对文风克隆、上下文装配、写后检查及写作模板的静态代码审查。尚未通过真实模型生成做效果对比；以下预期收益需要后续验证。本次只记录规划，不代表功能已经实现。

现有链路已经覆盖：参考原文 → 文风卡 → 上下文装配 → 正文写入 → 文风检查。优化重点是修复链路中的信息丢失与规则偏差，再改善样本选择和反馈机制。

实施时遵守现有 `docs/功能规划.md` 的数据契约与反目标：保留 Markdown 文件作为资料来源，不引入第二套正文存储，不自动生成整本小说，不增加不必要的运行时依赖。语义提炼与复核优先由会话 AI 完成，插件负责资料装配、确定性检查及结果记录。

## 二、P0：先修复正确性问题

### 1. 文风核心信息必须完整注入

**现状**：`index.js` 的 `stylePromptText` 与 `styleRuleText` 主要提取二级标题下的规则、锚点和禁忌。卡片顶部的“视角与时态”在正常提取路径中没有进入装配结果；每节只取前两条，可能丢失后续限制与正例；反例被排除；锚点从开头按字符截取。

**任务**：

- [x] 将视角、叙述权限、核心规则作为优先保留项。
- [x] 不再将每节前两条等同于该节全部有效规则；支持明确的规则优先级。
- [x] 在预算允许时装配卡片中的正例与反例；按场景相关性选择留到第 5 项。
- [x] 按完整片段选择锚点，避免在句子中间截断。
- [x] 返回装配清单，明确已包含、已省略的内容与省略原因。

**验收**：卡片顶部指定的限知视角出现在装配结果中；重要规则不会因所在行靠后而静默丢失；所有被选锚点保持完整，预算不足有明确说明。

**实施记录（2026-11-16）**：已实现顶部视角提取、`[必选]` 优先级、完整条目装配，以及 `style.included` / `style.omitted` 清单。省略项也会出现在工具文本结果中。3 项自动回归测试及 Node 语法检查通过；尚未进行 DSH 宿主端联调和真实模型生成对比。

### 2. 统一禁忌模板与解析方式

**现状**：`styleBanned` 把整行作为一个禁用字符串，并忽略超过 40 字的行；`templates/style-card.md` 却示范用“词：A / B / C”在一行列多个词。按模板填写时，可能无法按单词命中。

**任务**：

- [x] 将模板规范为一行一个禁用词，并为错误格式提供提醒。
- [x] 如需兼容旧卡，明确处理标签前缀与列表分隔符，避免破坏整句禁忌。
- [x] 区分禁用词、少用词、语义禁忌，避免全部使用字符串匹配。
- [x] 命中反馈携带原文片段与位置，便于局部修改。

**验收**：按模板创建的禁用词可逐项命中；整句禁忌仍能使用；语义要求不会被误当成需要在正文中寻找的字面字符串。

**实施记录（2026-11-16）**：统一一行一项模板，兼容旧卡多词与整句列表；禁用项命中携带行列位置，少用词仅提醒，语义禁忌列入待复核。7 项累计回归测试、语法与差异检查通过；尚未完成 DSH 宿主联调。

### 3. 统一上下文预算，避免长章改写丢稿

**现状**：`novel_context` 对不同模块分别分配额度，最终累计 `budgetUsed`，没有统一执行总量限制。改写模式只取本章前 6000 个字符，却要求保留全部情节并通过 `replace` 覆盖整章。只依赖该装配包改写长章时，存在遗漏后半章的风险。

**任务**：

- [x] 明确预算计量口径，统一调度各模块额度，说明其与模型 token 数的区别。
- [x] 计入最终装配文本的必要标题与指令开销。
- [x] 必要内容放不下时，明确提示并切换分段或分场景流程，不静默截断。
- [x] 全章覆盖前确认输入覆盖完整正文；分段改写保留未修改内容。
- [x] 改写先检查事实、动作和信息点是否保留，再检查文风。
- [x] 默认针对问题段落修订，避免每次节奏偏差都引导整章重写。

**验收**：超过 6000 字符的章节不会因装配截断而在覆盖时丢失尾部；预算不足有可执行的后续流程；历史版本机制继续有效。

**实施记录（2026-11-16）**：最终 `prompt` 统一按含空白的 Unicode 字符计量；完整章纲、改写原文与已选文风等必要内容超额时返回 `ready: false`，不发送残缺原文。新增分段上下文和哈希校验的 `patch` 保存，未改范围由插件保留；全章 `replace` 可传原文哈希检查。事实、动作与信息点的语义保留由会话 AI 按指令核对，插件尚不自动证明语义等价。预算针对最终提示文本，不包含结构化元数据、宿主封装或既有对话。累计 11 项回归测试通过；未进行 DSH 宿主联调。

## 三、P1：提高文风提炼与生成贴合度

**本轮实施记录**：新建克隆卡只包含待校准状态、统计观察与可回查锚点。停用通用短句和自动禁词规则，代词只显示计数。连续样本保留原始缩进、空行和短对白，使用启发式用途标签；单场景装配优先包含通用锚点和最多两个匹配锚点。会话入口提供证据提炼、试写和确认后回写指引，审稿增加视角与样本内容混入的核对。多场景装配仍按预算使用现有锚点，场景标签需复核。现有文风卡沿用原规则，真实模型对比、场景统计基准和宿主联调待验证。

### 4. 自动克隆只生成有证据的特征

**现状**：`composeStyleCard` 向不同样本添加相同偏好，例如短句只放特定位置、“别写成二十多字的长句”、断场依赖特定标点。这些并非从原作可靠推导，可能与样本相反。`cloneStyle` 还把样本未出现的部分套话直接变成禁忌。

**任务**：

- [x] 删除没有样本依据的固定写法结论。
- [ ] 区分统计观察、AI 提炼、作者硬性要求和待确认项。
- [x] AI 提炼的叙述习惯附对应样本证据。
- [x] “样本未出现”仅作为观察，不自动升级为禁止。
- [x] 自动生成卡标记为待校准，保留现有启用方式的兼容性。
- [x] 人称代词密度只作为视角线索，不作为限知或全知的最终判断。

**验收**：长句样本不会收到通用短句限制；没有证据的结论明确待确认；用户能分辨规则的来源。

### 5. 按场景选取样本，保留原始段落

**现状**：`sampleExcerpts` 过滤不足 20 字的段落后再拼接窗口，可能删除短对白与节奏重音；均匀抽取全文位置也无法保证覆盖不同场景写法。

**任务**：

- [x] 筛选样本窗口时允许过滤无关材料，但窗口内部保留短段、对白和原始断行。
- [ ] 为锚点添加用途标签：对话交锋、动作冲突、内心活动、环境描写、过场、章末等。
- [ ] 根据当前章纲或场景选择 1—2 个相关片段，并搭配整体叙述声调样本。
- [x] 样本记录来源位置，便于回查与重新提炼。
- [x] 明确样本用于学习表达，不应带入参考作品的人名、设定、事件或独特原句。

**验收**：短段密集的样本不会被采样过程改造成长段；对话场景优先获得对话样本；选入上下文的片段可追溯。

### 6. 增加试写校准与反馈沉淀

建议流程：提炼文风 → 同一场景试写 500—800 字 → 用户指出偏差 → 更新规则和正反例 → 正式写章 → 局部复核。

- [x] 提供简短试写流程，不要求用户一次判断整章。
- [ ] 区分局部修改与长期偏好，避免将一次批注自动推广到全书。
- [x] 将作者确认的长期偏好保存到当前文风卡。
- [ ] 区分剧情结构要求和文风要求，明确冲突处理方式。
- [ ] 将爽点、钩子、内心材料等要求按作品需求配置，不把某类小说的写法视为所有文风的默认要求。

**验收**：“这一段太啰嗦”只影响本次局部修改；“以后不要替人物解释情绪”经确认后作为长期规则进入后续装配。

**AI 克隆实施记录**：点击「克隆文风」后，当前会话模型在保存前分析带行号的原文样本。模型选择已展示的行号，插件直接回填原文并复核；行号无效时自动再提炼一次。保存后，写作装配使用 AI 提炼的表达规则和场景锚点。宿主联调及真实试写对比待验证。

## 四、P2：改进检查与效果验证

### 7. 从整章均值扩展到局部证据

**现状**：`styleFit` 真正触发漂移报警的指标主要是平均句长和句号密度。场景构成不同会自然造成指标变化；指标接近也不能证明叙述方式接近。

- [ ] 将统计结果明确命名为节奏偏差提示，不等同于文风质量判断。
- [ ] 逐步增加分布信息与场景基准，避免只看全书均值。
- [ ] 由会话 AI 根据规则执行语义复核，并返回正文证据。
- [ ] 检查限知视角越界、过度解释情绪、人物声口趋同、重复叙述套路。
- [ ] 检查参考作品专有名词、事件和明显原句是否混入正文。
- [ ] 反馈使用“位置 + 规则 + 证据 + 修改建议”，不以单一相似度分数替代判断。
- [ ] 语义复核无法确定的项标为待判断，避免把推测变成强制改写要求。

**验收**：场景变化不会仅凭整章均值就被断言为文风失败；复核意见可以定位到段落，支持有针对性的修改。

### 8. 建立固定效果对比集

- [ ] 准备对白、动作、心理、过场四类固定写作任务，并覆盖不同风格样本。
- [ ] 在相同模型、生成设置和任务条件下比较改动前后结果，必要时重复生成。
- [ ] 记录装配内容、文风卡版本和样本来源，保证结果可追溯。
- [ ] 评价规则遵循、事实遗漏、人物声口、重复套句、参考内容混入及用户偏好。
- [ ] 对关键确定性逻辑增加回归验证：规则注入、禁忌解析、完整样本保留和长章改写完整性。

**验收**：能够明确指出哪些改动改善了哪些问题，而不是仅以统计报警减少判断效果提升。

## 五、推荐实施顺序

| 阶段 | 工作重点 | 交付结果 |
| --- | --- | --- |
| 第一阶段 | 规则注入、禁忌解析、预算与长章完整性 | AI 看得到关键要求，改写不会因截断遗漏正文 |
| 第二阶段 | 克隆去固定偏好、场景样本、试写校准 | 文风来源有证据，生成能针对场景学习写法 |
| 第三阶段 | 局部语义复核、固定效果对比 | 修改有依据，优化收益可以复查 |

优先投入“完整传递文风规则、按场景选择原文样本、通过试写校准”。实施中持续更新本文件勾选项，并同步维护实际改变的数据契约、模板和工具说明。
