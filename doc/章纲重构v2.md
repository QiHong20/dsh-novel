# 章纲重构 v2：小说表现力与分层审核

> 日期：2026-11-18。状态：功能已实施，自动化与独立浏览器验收通过；真实生成质量待验证。
> 本轮已按规划实现功能。承接 `章纲功能重构(人物).md` 的场景、人物认知与历史确认模型；不增加旧数据迁移任务。

## 一、目标

第一轮以场景组织人物、认知和事件，为连续性提供了基础。本轮解决两个问题：

1. 场景组织不能让小说退化为只有动作和对白的剧本，需要适当的心理描写与人物登场呈现。
2. 章纲关联信息增加后，作者难以审核，需要将剧情骨架与人物、事件详情分层展示。

目标是：作者在一级章纲页快速判断“这一章发生什么、是否合理”，再进入二级页核对“人物为什么这样想、这样说、这样做”。AI 写作仍获得完整的必要约束，不因界面精简而丢失上下文。

## 二、现状与需要纠正的规则

根据本轮静态代码检查：

- 人物卡已有外貌锚点要求，写作提示要求在初登场或关键对峙时带出这些特征。
- 现有心理相关规则仍会要求章纲补 1–2 条“心里”，部分提示要求采用“情绪｜台词”并逐字写入正文。
- 新场景人物安排已有目标、情绪、认知和表达意图，但心理描写与登场呈现还没有明确的结构。
- 章纲主界面仍容易将整节 Markdown 当成审核正文，人物约束和事件资料使页面膨胀。

本轮应替换相互矛盾的提示，不能只追加一段新要求而保留旧的强制规则。第一轮规划和实施记录仅作背景，落地前重新核对当前代码，避免覆盖后续改动。

## 三、心理描写：按关键节点安排，不按数量填充

### 1. 写作原则

- 主角和配角都可以有心理活动，不按人物地位限制。
- 是否直接呈现内心取决于本场叙述视角与作品文风，不因为人物重要就允许随意进入其内心。
- 优先在重要决定、误解、认知改变、情绪与行为相反等节点安排心理描写。
- 对白和动作已经表达清楚时，不重复追加心理解释。
- 不要求每章固定几条、每场固定一条，也不要求每句对白后跟随内心独白。
- 心理描写可以是直接心声、短暂联想、回忆片段、自我说服、迟疑或间接叙述，不强制写成可逐字复制的台词。

“人物有某种心理”与“正文直接写出这种心理”分开处理。非视角人物的真实想法可以作为作者侧动机安排，但不能自动获得正文中的直接展示权限。

### 2. 章纲表达

心理描写挂在具体场景的具体人物上，建议支持以下可选信息：

| 信息 | 用途 |
|---|---|
| 心理触发 | 哪个动作、对白或信息引发心理活动 |
| 心理内容 | 这一刻想到什么、如何理解、有什么矛盾 |
| 叙事作用 | 解释决定、展现误解、埋下遗憾、形成表里反差等 |
| 表达方式 | 心声、联想、短回忆、间接叙述、仅作者参考等 |
| 展开程度 | 一闪而过、简短展开、关键展开；不强制字数 |
| 视角权限 | 可直接呈现，或仅通过外部行为间接呈现 |

不要求填满所有字段。简单场景允许一条自然语言说明，复杂心理节点再展开；具体 Markdown 语法在实施时统一，本文示例不是已经生效的解析契约。

示例：

> 女主道谢时，主角想到此前没能救下的那个人，因此回避她的目光。作用是解释回避，并埋下过去的遗憾。用短暂联想呈现，不展开完整回忆。

非视角人物示例：

> 女主误以为主角嫌她拖累，这是作者侧心理依据。本场采用主角限知视角，只表现为她收回感谢、主动拉开距离；不直接写出她的想法。

### 3. 提示与检查调整

- 删除“没有心理条目就补固定数量并重写整章”的规则。
- 删除将所有心理内容强制转成“情绪｜台词”、要求逐字写入正文的规则。
- 区分章纲中的心理材料与作者明确指定必须保留的内心原句，后者才有原句保留要求。
- 心理相关关键词和密度只能作为观察线索，不能证明缺少心理描写，也不能据此强制增加心理段落。
- 当章纲明确安排了关键心理转变时，检查正文是否有相应表达；语义核对需结合原文给出依据，不能仅凭关键词判断落实。
- 心理内容仍受认知边界约束，不得回忆尚未经历的事件或知道尚未获得的信息。

## 四、人物登场呈现：形成可辨认的第一印象

### 1. 写作原则

- 重要人物首次正式登场时，章纲应考虑是否需要外貌与气质呈现。
- 身材体态、面容、衣着、姿态、声音和标志性物件均可选用，按人物与场景取舍。
- 描写通过观察者和当场动作自然发生，不要求停下剧情完成一套全身扫描。
- 后续出场优先唤起既有特征或表现变化，不反复复制完整外貌段落。
- 外貌帮助读者辨认人物；人物的重要性仍由行动、关系和剧情分量建立，不用美貌或描写篇幅代替叙事定位。
- 不只给女主安排外貌，男主、男二、女二、重要配角及反派均按实际需要处理。

### 2. 区分不同的“第一次”

至少区分以下情形：

- 读者第一次正式看到这个人物。
- 当前视角人物第一次见到这个人物。
- 人物已被提及，但尚未正式出场。
- 人物以伪装、陌生身份或变化后的形象再次出现。

不能仅根据正文首次出现姓名推断首次登场。作者或会话 AI 可明确标记，历史资料不足时标记待核对，不自动下结论。

### 3. 本章人物安排

增加可选的“登场呈现”信息：

| 信息 | 用途 |
|---|---|
| 登场性质 | 初次正式登场、视角人物初见、再次出场、形象变化 |
| 观察者 | 谁在看，其注意力、经验和认知如何影响描写 |
| 本场描写重点 | 从人物卡选择与本场有关的特征，不复制全部外貌设定 |
| 呈现时机 | 在什么动作、互动或停顿中自然带出 |
| 第一印象 | 希望读者或观察者形成什么印象；主观印象不等于客观事实 |
| 已呈现与新增 | 哪些已经写过，哪些是本场新增或发生变化的部分 |

示例：

> 女主首次正式登场。主角注意到她高挑的体态、略显疲惫的眼睛，以及与衣着不相称的旧手表。她俯身查看伤口时自然带出这些特征，留下“干练，但似乎刚经历过什么”的第一印象。

人物卡继续保存稳定外貌设定；本章只记录选取哪些特征、如何呈现。读者已经见过什么，应以实际正文及有效来源为依据，不把章纲计划当成描写已经完成。

### 4. 检查边界

- 对明确标记为重要人物首次正式登场、但没有呈现安排的场景给出温和提醒。
- 提醒允许合理例外，如刻意隐藏面容、黑暗中见面或人物暂时仅以声音出现。
- 不以外貌词数量、形容词数量或描写字数作为是否合格的硬指标。
- 后文外貌与人物卡冲突时，先核对是否属于伪装、观察误差或随经历发生的变化，不直接判错。

## 五、右栏分层：一级审核剧情，二级审核关联资料

### 1. 一级章纲页

主页面默认只呈现：

- 章节标题与本章目标。
- 按顺序排列的场景摘要：谁做什么、遇到什么阻力、结果如何。
- 关键转折、落点与收尾钩子。
- 人物、事件线、待核对事项的入口及数量。

不直接展开逐人物认知、心理、外貌、完整历史与证据。不是将整份原始 Markdown 简单折叠，而是从同一份结构化资料生成便于审核的剧情视图。

示意：

```text
第八章：客栈对质
本章目标：让女主开始怀疑救援与家族有关。

场景一：女主追问，主角回避。
场景二：信物出现，男二加深误解。
收尾：女主决定独自查证。

[人物 3]  [事件线 2]  [待核对 1]
```

场景上可保留人物快捷入口和简短问题标记，点击后打开对应的二级详情。

### 2. 本章人物页与角色详情

点击“人物”进入本章人物列表，显示姓名、叙事定位、参与场景与待核对状态。点击具体人物进入其本章详情，可按场景依次审阅：

1. 入场认知、关系与信息来源。
2. 当前目标、情绪和表达意图。
3. 心理描写安排及视角权限。
4. 登场外貌安排与观察者。
5. 场内触发和计划离场变化。
6. 正文实际确认的变化、证据与复核状态。

角色详情提供“查看全局人物卡”入口，但默认展示本章情况，不跳进全书资料后让作者自己寻找本章内容。

认知、心理材料和展示权限分开展示，尤其明确“仅作者参考”的非视角人物心理，避免审阅时误以为必须直接写进正文。

### 3. 本章事件线页

只展示本章关联的事件线与具体事件节点：

- 之前已确认推进到哪里。
- 本章计划推进什么。
- 哪些场景和人物参与。
- 正文实际落实情况及待核对事项。

提供全书事件线入口，但不在本章详情默认铺开整条事件线。已发生事实与规划仍然分开。

### 4. 待核对页

集中展示认知冲突、引用缺失、来源失效、视角权限疑点和未落实的关键安排，点击问题定位到具体人物或场景。

区分结构性问题与需要语义判断的问题。没有心理条目、缺少外貌安排等提醒不能自动升级为硬错误。

### 5. 导航与编辑

- 二级页顶部明确显示“当前章 / 人物或事件 / 当前对象”，提供返回入口。
- 返回时恢复原章节、滚动位置和展开状态。
- 角色详情切换场景时保留正在审核的人物；事件详情可定位关联场景。
- 默认编辑剧情骨架或当前角色的本场安排，不要求作者在大段 Markdown 中定位字段。
- 局部编辑只更新对应内容，保留其他角色、事件、未知字段和正文；必要时保留“查看/编辑原始章纲”作为高级入口。
- 未保存编辑切换页面时避免静默丢失，提供保存或保留草稿的明确行为。

## 六、数据与 AI 上下文

### 1. 一份数据，多种审核视图

继续以现有章纲、人物卡、事件线和人物历史作为资料来源。精简章纲、人物详情和事件详情均为派生视图，不另存一份“精简版章纲”，避免双份内容失同步。

心理与登场安排归属于“场景中的人物”，不覆盖全局人物卡。长期设定仍在人物卡，已确认认知和关系仍在人物历史中维护。

### 2. 界面精简不等于装配精简

AI 扩写章纲时，应获得当前场景的叙述视角、人物认知、动机，以及是否需要心理和登场安排的提示。

AI 扩写正文时，应获得：

- 剧情骨架与场景推进要求。
- 出场人物相关设定、当前认知和表达意图。
- 本场需要的心理材料、表达方式及视角边界。
- 登场描写重点、观察者和呈现时机。
- 相关事件与计划变化，明确其尚未发生。

认知与视角权限属于必要约束；重要心理转变和首次登场安排按本场需要保留。预算不足时明确报告并按场景装配，不能因作者界面隐藏了详情就把这些信息漏掉。

### 3. 修改后的连续性

- 只修改心理表达方式，不应自动产生新的已确认认知。
- 计划新增外貌描写，不应立即标记为读者已经看过。
- 修改正文后，相关来源与确认记录按现有机制重新核对。
- 整场移动时连同心理、登场与人物约束一起移动，保持稳定场景 ID。

## 八、验收场景

| 场景 | 预期结果 |
|---|---|
| 普通过场，没有必要的心理转变 | 不要求为了凑数增加心理描写 |
| 主角答应帮忙，但内心抗拒 | 可安排心理反差，不重复解释每句对白 |
| 非视角配角产生误解 | 保留作者侧动机，通过可观察行为呈现，不随意进入其内心 |
| 作品明确采用全知视角 | 允许按文风展示配角内心，不机械套用限知禁令 |
| 心理材料是短暂联想 | 不强制改成一段明确的内心台词 |
| 女主首次正式登场 | 能审阅观察者、外貌重点、动作时机和第一印象 |
| 女主此前被提及，但未出场 | 不把姓名出现当成已完成外貌描写 |
| 重要男配或反派首次出场 | 同样支持人物呈现，不只对女主生效 |
| 再次遇见已有完整描写的人物 | 优先唤起特征或表现变化，避免重复扫描 |
| 人物在黑暗中出现 | 允许声音或动作建立印象，不强制完整外貌 |
| 一级章纲关联多个角色和事件 | 默认仍可快速看清剧情，详情通过二级入口查看 |
| 查看女主详情后返回章纲 | 恢复原章节位置，不重新从列表顶部找起 |
| 修改某角色的心理安排 | 不覆盖其他人物、事件或正文，也不自动确认新认知 |
| 移动场景到下一章 | 心理与登场安排随整场保留 |
| 界面隐藏人物详情 | AI 上下文仍包含写作所需的信息与视角限制 |
| 正文没有落实计划中的首次外貌描写 | 不将计划标记为已经向读者呈现 |

## 九、范围控制

本轮不建立复杂心理数值系统，不设心理段落或外貌词的硬性配额，不根据姓名出现次数自动判断人物地位，不另建第二份章纲数据。

主要交付是写作规则与提示的统一、人物在场景中的表现安排，以及便于作者审核的分层界面。具体字段应以少填、可继承、可追溯为原则，避免增加一套必须逐项填满的表格。


## 十、实施记录（2026-11-18）

- `stage.js`：解析角色心理、登场字段与场景视角；生成一级摘要、表现核对清单及事件详情；以全文件指纹保护局部字段编辑。正文确认的 `呈现` 记录按阅读顺序参考，不进入角色认知。
- `index.js`：工具提示、上下文及写后检查统一新规则；移除心理数量、逐字心声与密度强制要求；语义待核对项与机械错误分开；提供 `novel_stage_edit` 和受原写入防护保护的局部编辑接口。
- `client.js`：首页剧情骨架、人物列表及详情、事件详情、场景编辑和核对页；来源定位、候选确认与撤销、局部字段编辑及原始章纲入口。返回恢复首页位置，未保存草稿按会话和对象保存于 sessionStorage，过期版本不会覆盖文件。
