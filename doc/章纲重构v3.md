# 章纲重构 v3：正文上下文中的人物表现层

## 一、目标与范围

当前人物资料、场景认知和人物历史已经能较好支持正文生成。本轮主要解决两个问题：

1. 章纲缺少角色描写锚点，尤其是初次见面时，AI 容易忽略长相、身材、衣着、声音等人物表现。
2. 心理与对白缺少情绪依据，AI 容易只完成事件扩写，人物像执行章纲的工具。

优先改造 `novel_context` 的正文上下文装配，不要求作者先把所有章纲改写成完整的心理脚本。上下文可以显著增加；用户接受约 100KB 甚至更大的材料开销，优先考虑章节质量。

本文保留设计依据，实施状态见文末；实际落地范围和待评估事项分开记录。

## 二、现状与缺口

### 2.1 已有基础

`stage.js` 已支持以下人物块字段：

- 心理：心理触发、心理内容、叙事作用、表达方式、展开程度、视角权限、保留心声原句。
- 登场：登场性质、观察者、描写重点、呈现时机、第一印象、已呈现与新增、不描写原因。
- 场景状态：目标、关系与情绪、表达意图、触发、计划变化，以及认知约束。

现有场景上下文也会提供有效的已确认人物历史、读者此前已见的呈现记录，并提示计划不等于事实、未记录不代表从未描写。

这些能力应保留并复用，不另建一套相互竞争的人物事实系统。

### 2.2 主要缺口

现有表现字段主要依赖作者或 AI 在章纲里提前填写。字段为空时，正文上下文主要提供通用原则，缺少将人物资料转化为本场表现机会的桥梁。

目前 `index.js` 中的装配还存在以下限制：

- 续写默认预算为 12000 Unicode 字符，改写默认 16000，最高 40000。
- 人物卡是可因总预算不足而省略的条目。
- 上章结尾最多约 800 字符，可能只保留事件结果，遗漏情绪形成的过程。
- 续写文风材料内部额度最高 2800 字符，改写最高 3000；单独调大总预算不能解除这些限制。
- 章纲原文与场景人物约束可能重复展示，新增容量应优先用于有价值的材料。

因此，本轮不能只增加一句“加强心理描写”，也不能只提高总预算。

## 三、核心设计：新增本场人物表现上下文

在人物资料、认知约束和剧情计划之上，增加按场景组织的“本场人物表现”层。

该层负责组织依据、指出缺口、提出需要考虑的表现机会；正文 AI 负责结合情境作出创作判断。普通装配程序不能通过关键词可靠推断人物隐秘动机，不应自动生成并认证情绪事实。

### 3.1 描写锚点：从静态资料到观察机会

每个场景按需要提供：

- 观察者是谁，为什么此刻会注意这个人物。
- 对读者而言是否首次正式登场，对观察者而言是否初次见面，两者分别判断。
- 人物卡中哪些体态、面容、衣着、声音和习惯特征与本场有关。
- 当前距离、光线、遮挡、伪装和动作是否允许观察到这些特征。
- 相关特征可能影响观察者的什么判断；推演内容必须标为可选，不能冒充既定事实。
- 读者此前已经见过什么，此次有哪些有依据的变化值得呈现。
- 缺少依据或不适合描写的原因。

例如，在人物卡已有“身材高挑、衣着整齐”等资料，且现场确有低矮屋门的前提下，可给出这样的表现机会：

> 入门动作可以自然带出身高。视角人物正在怀疑来者身份，可考虑让其注意衣着与环境的关系。使用已有特征，不必逐项扫描外貌。

重要原则：

- 不能将“没有呈现记录”判定为“首次登场”。
- 不凭空补出伤疤、瞳色、体型、身世等稳定设定。
- 读者已见过的人，仍可能是某个角色第一次见到；应写该角色的关注与判断，而不是重复人物介绍。
- 描写可以服务于吸引、戒备、身份判断、关系变化或单纯的鲜活感，不要求每处细节都承担伏笔。
- 不设外貌特征数量、固定篇幅或每次出场必写的配额。

### 3.2 心理锚点：提供因果与选择空间

避免只提供“愤怒、紧张、悲伤”等标签。优先组织以下因果材料：

> 此刻在意什么 → 受到什么刺激 → 如何理解刺激 → 想采取什么行动 → 为什么压住或改变行动。

可用依据包括人物目标、已知与误信、关系历史、前文未解决的冲突，以及章纲明确指定的心理材料。

重点考虑关键决定、误解、认知转变、期待落空和关系变化。不是每一拍都要完整走完心理链，也不是每句话后面都要解释。

表达可以采用短暂念头、联想、短回忆、间接叙述、迟疑、选择改变或有意义的沉默。直接内心必须遵守场景视角；其他人物的内心资料只能作为作者参考，通过允许的行为和对白表现，不得越权读取。

### 3.3 对白锚点：目的、掩饰与回应

为关键对话组织以下材料：

- 说话人想让对方知道、相信或做什么。
- 说话人不愿让对方察觉什么；有依据时才提供，不能默认每句都有隐情。
- 双方目前的关系、权力位置和信任程度。
- 表面说法与真实诉求是否存在有依据的差异。
- 对方的回应是否改变了说话策略。
- 人物卡中的声口习惯，以及相关前文中的实际对白样本。

同样一句“你怎么来了”，可能对应不同处境：想赶人却不能暴露关系；盼着对方来却不肯示弱；担心对方涉险，需要确认有没有被跟踪。这些只是说明机制的示例，不是可直接套入作品的事实。

目标是让对白从人物处境中生长，不强制每句对白配动作、神态和心理说明，也不将所有人物都写成擅长试探和算计的人。

## 四、补足前文情绪承接

上章末尾继续作为直接衔接材料，但增加按本场人物和关系选择的相关原文：

- 最近一次有关系影响的冲突、承诺、拒绝、分别或和解。
- 与当前心理触发直接相关的事件。
- 已有外貌呈现与人物声口样本。
- 对当前场景仍有影响、尚未解决的情绪来源。

每段附章节来源和必要上下文，避免只截出一句含糊的情绪标签。历史材料表明过去发生了什么，不自动证明人物现在仍保持同样的情绪。

优先复用已有有效历史记录及其正文依据；缺少记录时可提供待模型核对的原文候选。检索命中不是语义认证，不因名字同段出现就判定两人有直接互动。

不得使用当前续写时点之后的内容推断角色认知；改写模式中的现有正文也应明确标为待改文本，不能自动作为更早时点的历史。

## 五、输出分层与事实边界

| 层次 | 职责 |
| --- | --- |
| 人物卡、已有正文、有效历史记录 | 提供有来源的事实与表达素材 |
| 章纲 | 提供事件、目标和作者明确指定的表现要求 |
| `novel_context` | 按场景聚合材料，展示缺口与可考虑的表现机会 |
| 正文 AI | 在事实、认知和视角边界内完成临场推演与文学表达 |

表现包必须清楚区分三类内容：

1. **明确要求**：作者指定的心理、登场和对白意图，遵守其范围与触发时机。
2. **有依据的可选展开**：允许正文 AI 结合素材进行创作，不是强制清单。
3. **资料不足或待核对**：说明未知范围，不自行填成事实，不把缺少记录当作否定证据。

临时推演不自动回写章纲、人物卡或历史。计划变化只有实际写入正文并经过已有提取、核对流程，才可进入相应历史。

建议按场景展示以下结构，空项可合并为简短缺口提示：

```text
场景与视角
  明确的剧情及人物表现要求
  人物资料与相关原文依据
  描写机会：观察者、可见特征、此前呈现、当前变化
  心理依据：在意之事、触发、理解与选择
  对白依据：目的、关系、声口、回应后的策略变化
  待推演问题与资料缺口
```

旧版逐行章纲也应获得通用表现指导和相关人物材料；不能因为没有结构化场景就完全失去本轮能力。无法可靠划分场景时明确限制，不伪造场景或人物归属。

## 六、写前推演指令

正文上下文应要求 AI 在动笔前检查：

- 当前场景谁值得被观察，观察者此刻会注意什么。
- 哪些人物的情绪需要承接前文，依据在哪里。
- 哪个刺激会改变人物的理解、决定或说话方式。
- 关键对白是否出于人物自身目的，是否符合其声口和当前关系。
- 章纲未填写表现字段时，是否仍有充分依据自然展开。

推演可以作为生成前的简短工作规划，不要求将完整分析输出为小说正文，也不要求对每个角色、每句对白填写一套表格。

局部改写时仅服务于选定范围，不借表现补强改变范围外事实或扩写整章。

## 七、预算与装配策略

同步调整总预算和内部材料配额，而非只修改最高值。

- 优先保证本场人物资料、核心认知边界、作者明确要求和关键承接原文。
- 增加相关前文与文风样本空间，避免仍被旧的小额度截断。
- 对冗余章纲和重复约束做合理合并，保留来源与可追溯性。
- 保留明确的装配清单、实际用量和省略提示；材料不足时不能声称已核对完整上下文。
- 容量充足时不必主动压缩关键材料，也不为凑满容量添加无关历史。

现有预算单位是 Unicode 字符，100KB 是字节量，两者不能直接等同。实施时需保持参数、文档与统计单位一致，并结合实际返回长度验证。

## 八、实施顺序

1. 在 `novel_context` 中增加场景人物表现包，复用现有心理、登场、关系和表达意图字段。
2. 补充空缺字段情况下的写前推演指导，明确事实与可选创作边界。
3. 增加相关前文原文承接，优先使用已有历史依据，再提供可核对的检索候选。
4. 调整总预算、人物资料优先级、上文与文风内部额度，处理重复材料。
5. 完善旧章纲兼容、局部改写边界、来源展示与省略提示。
6. 使用真实写作场景评估生成效果，避免仅凭提示词包含新术语就认定完成。

本轮优先项是“场景人物表现包 + 相关前文承接 + 空缺锚点的写前推演指令”。暂不要求新增大量章纲必填字段，不重做现有认知历史体系。

## 九、验证与验收

功能验证重点：

- 章纲未填写心理和登场字段时，仍提供表现指导与相关依据。
- 已明确填写的要求被完整保留，可选建议不会覆盖作者要求。
- 区分读者首次登场与角色初次见面；没有记录时不误判。
- 有足够预算时本场人物卡与关键材料不被意外省略；不足时清楚报告。
- 相关原文具备来源，不混入未来剧情，不把历史情绪当作当前事实。
- 限知视角不直接展示非视角人物内心，局部改写不越界。
- 支持旧版章纲及缺失材料，不因字段为空而伪造事实。

写作效果评估应使用相同人物卡和章纲对照生成，覆盖首次见面、再次见面、关系冲突、情绪延续及平静交流等场景。重点人工判断：

- 描写是否自然进入观察和动作，而非集中罗列外貌。
- 心理是否推动理解与选择，而非重复解释已经清楚的对白。
- 对话是否体现不同人物的目的、关系和声口。
- 情绪是否承接前文，且会随现场刺激变化。
- 是否出现重复描写、过度心理解释、无依据动机或视角越界。

不以外貌数量、心理词频、动作密度或固定篇幅作为质量通过标准。装配逻辑测试只能证明材料和边界正确，文学效果仍需实际生成与人工审阅。

## 十、实施记录

已接入 `novel_context`：

- 新增 `lib/presentation.js`，按场景人物的已有字段提供缺口指导，并复用有效历史的证据索引；旧章纲也提供通用表现指导。
- 表现包与本场人物卡作为必要材料，预算不足时明确返回未就绪，不静默丢弃人物资料。
- 检索目标章之前的正文，按人物姓名选择近期原文及相邻段落，标注章节、段落与候选性质；不截断单个证据段落，不把检索结果认证为历史。
- 续写默认 60000 Unicode 字符，改写 80000，上限 200000；上章结尾最多 6000，文风续写最多 12000、改写最多 16000，相关前文最多 20000，仍受总预算限制。
- 局部改写明确限制范围；倒叙明确区分章节顺序与故事时序，候选原文不得直接变成角色认知。

当前前文检索是姓名匹配的候选召回，并非语义关系检索，可能遗漏别名、代词或很早的关键互动；需结合已有历史或按需补读。候选原文因总预算不足可整块省略，并在装配清单中报告。已有章纲和场景约束的重复展示暂保留，以避免丢失原文约束。

自动测试覆盖表现指导、旧章纲、局部范围、原文候选语境、配额与人物卡必要性。真实作品的文学效果尚待生成对照与人工审阅，不以测试通过宣称章节质量已获认证。

### 诊断含义修正

- 场景警告保存结构化归属，按本章或指定场景过滤，不依赖场景 ID 的命名。全局 ID 冲突及影响当前场景的失效历史仍保留；移动场景后，其原历史失效提示仍可追踪。
- `novel_check.historyCoverage` 单独返回入场历史覆盖信息，不再生成 `stage-history-gap` 问题。无更早出场场景是正常起点；后续场景缺少记录是资料覆盖提醒，均不证明正文错误，也不要求为清零补造历史。
- 人物表现要求保留在 `presentationReview` 中，展示时汇总为一项审阅清单，不逐条渲染为待处理提醒。它们不会因审稿登记而从章纲消失，也不应以清空清单为目标。
- 真实案例《修仙系统文》第一章复测：无关章节的 8 条警告不再进入报告；7 条历史状态分为 2 处无更早场景、5 处后续场景未记录；11 条表现要求保留为审阅依据。语义审稿仍为 pending，不伪装为已审阅。
- 修订标识为 `scoped-diagnostics-v2`；49 项自动测试通过。已运行的宿主需要加载新代码后才会返回此修订。
