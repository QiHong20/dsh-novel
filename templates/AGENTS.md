# 这本书的写作约定（给 AI 的作业规范）

这个目录是一本小说，不是代码项目。下面是**唯一可信的格式约定**——按它写，右栏的章节/章纲/人物/设定/大纲五个页面和 `novel_*` 工具才能正确读到。

## 目录结构

```
book.json          章节清单（真相来源：章节 id、标题、文件、状态、目标字数）
outline.md         整本大纲（一句话 / 主线 / 约束）
beats.md           章纲（每章一节，写正文前先看它）
threads.md         伏笔表（人工维护的 Markdown 表格）
characters/        人物卡，一人一个 `名字.md`
settings/          设定，一个条目一个 `条目名.md`
chapters/0001.md   正文，一章一个文件
```

**不要新建别的目录来存稿子**，也不要复制一份到别处——`chapters/` 是唯一正文所在。

## 作者不会说工具名，你要自己翻译

作者只会用日常说法，把"想要什么结果"讲出来。你负责选工具，不要让他先学工具名，也不要反问他"要不要用 novel_write"。对照表：

| 他说 | 你要做 |
|---|---|
| 「拆一下这本书」「这本书帮我拆下书」 | **把它建成一本能接着写的书**：先 `novel_import({ source, dryRun: true })` 看清切出来多少章，再 `novel_import({ source, limit: N, replace: true })` 把原文**搬**进 chapters/（不要自己抄正文）→ 需要摘要时再用 `novel_write` 补 → `novel_card` 主配角 → `novel_setting` 地点/规矩/物品 → `novel_threads` 埋设与回收 → `novel_beats` 每章场景 + `→ 爽点` / `→ 钩子`。**不要交分析报告当成果** |
| 「写第三章」/「接着写」 | `novel_context({ chapter })` 拿装配包 → 按它写 → `novel_write` → `novel_check` |
| 「这章有问题吧」/「帮我查一下」 | `novel_check({ chapter })`，然后只讲要改的三件事 |
| 「按 XX 的风格写」 | 有文风卡就 `novel_context` 带上；没有先 `novel_style({ clone: true, source })` 克隆一张 |
| 「加个人物」「这个人改成…」 | `novel_card`（一张一个文件，含 `## 关系` / `## 状态`） |
| 「记一条设定」 | `novel_setting`（一条一个文件，首行 `- 分类：…`） |
| 「埋个伏笔」「这个伏笔收了」 | `novel_threads`（不要手改 `threads.md`） |
| 「列个章纲」「这章要有哪几场」 | `novel_beats`（3–6 条 `- 场景：…`，末尾 `→ 爽点（类型）` / `→ 钩子`） |
| 「大纲看看」/「改大纲」 | `novel_outline` |
| 「这版不如上一版」/「回到刚才那稿」 | `novel_history` 看时间线 → `novel_restore` |
| 「这本书现在什么状态」 | `novel_status` |
| 「导入我写的 txt」 | `novel_import({ source, dryRun: true })` 探测切分 → 确认后 `novel_import({ source })` 原样搬进 chapters/（边界怪就给 `ranges`/`pattern`）→ `novel_status` 核对 |

两条底线：**正文只走 `novel_write`**（用 `write` 直接写 `chapters/` 会没有历史版本）；**"拆书"默认是要建书，不是要报告**。

## 人物卡格式（最容易写错，务必照抄小节名）

```markdown
# 老周

一句话说清这个人是谁。（这一行会成为「摘要」）

- 表面：爱笑，记性好。
- 里子：账册的旧主人。
- 外貌锚点：一双总笑成弯月的眼睛，袖口常年别着一枚擦得发亮的铜算盘扣。
- 性格：重情义又精明，遇事习惯先笑三秒再把账算清；底线是自己人绝不亏待、外账绝不留糊涂字。
- 口癖：称林小满为「少东家」。
- 说话：老掌柜腔，温厚里带点幽默反问，句尾爱落「呢/啊」缓和气氛，从不板着脸训人。「少东家，这账可不是这么算的——您先喝口茶，听老头子慢慢掰扯？」

## 关系
- 林小满：看着长大的孩子。
- 林小满 @0004：少东家开始不信他了。

## 状态
- @0003 去世（雾港码头失足落水）
- @0004 现身（其实没死，躲在旧货铺后屋）
```

规则：

- `## 关系` 下只能是 `- 名字：说明`；名字后可跟 `@0004` 表示「第 4 章起才成立」。**只记起点，不记终点**。
- `## 状态` 下只能是 `- @0003 状态说明`；一条状态持续到下一条为止。不含死亡词的状态（现身/复活/回到雾港）＝又活着了。
- 死亡词：去世 / 死亡 / 死 / 殁 / 阵亡 / 身亡 / 牺牲 / 遇难 / 丧命 / 不在了。写「没死、假死、装死」**不算**死。
- 这两节之外，`名字 @0004` 这种写法没有任何效果，别在别处用。
- 只写这本书里**真的会用到的**人物，路人甲乙不要建卡。

## 设定格式

```markdown
- 分类：规矩

雾港的规矩：收伞只能门外、雾天不点灯、簿子不外借。
```

首行必须是 `- 分类：...`（地点 / 规矩 / 物品 / 术语 / 组织 / 历史 / 其他），第一句正文会成为摘要。**一个可被点名的东西一条**：写第三章需要的是「账册」这一条，不是整本世界观。

## 章纲格式

```markdown
## 0003 第三章 旧客

- 场景：林小满 → 旧货铺后屋 → 想找老周问账册 → 撞见后屋有人住过
- 场景：老周 → 码头 → 想把册子沉进水里 → 被人叫住
```

二级标题以 **4 位章 id 开头**，一节 3–6 条场景，一条场景写清「谁 → 在哪 → 想干什么 → 撞上什么」。**只写一章的章纲**，别一次把四章填满。章纲里不写对白和描写。

**节奏标记（写在场景末尾，插件会统计，不另建表）**

```markdown
## 0007 第七章 开户

- 场景：江野 → 银行柜台 → 想开户存第一笔钱 → 撞上柜员要单位证明 → 转折
- 场景：江野 → 把批条推过去 → 柜员脸色变了 → 爽点（信息压制）
- 落点：出门时有人叫住他。钩子：王厂长在车里等着。
```

- `→ 爽点（类型）`：这一场给了读者情绪回报。类型写打脸 / 翻盘 / 揭秘 / 情感兑现 / 强强对话 / 信息压制 之一。
- `→ 钩子`：章末留翻页理由，**每章至少一个**。
- `→ 转折`：这一场把方向拐了个弯。
- 「爽点」是**这一场戏怎么演**的属性，不是一本账：**别单独建爽点表、别写到 outline 里当清单**。outline 的 `## 爽点节奏` 只写预算（`打脸×3`），实际有几处由章纲标记现算。
- 右栏章纲页顶部会显示「爽点 N · 有爽点的章 X/Y · 最长断档 K 章」；`novel_check` 会对没有爽点 / 没有钩子的章报 `no-payoff` / `no-hook`。

**信息行（`- 信息：…`）—— 不是场景，别拿它凑数**

```markdown
- 信息：现在是 1998 年 9 月，他回到了十六岁
- 信息：三天后厂里会出事
```

- 判据：**能被拍出来的写 `- 场景：`**（有地点、有对手、结束时状态变了）；只在人物脑子里发生的（回忆、推断、前情交待）写 `- 信息：`。
- 回忆**不占场景位**：它挂在某个场景的「撞上什么」里（例：`撞上安全气囊弹开、玻璃碎进嘴里，他记得有人在车外敲了三下窗`）。整章都在前世时才当场景写。
- 一章最多 3 条信息；只有信息行、没有场景行 = 结构错误（`info-only`）；正文里没落地会被 `info-missing` 点到。
- 前世的**事实**（洪水、改制、谁死了）要落成 `settings/` 条目，不要只写在章纲或信息行里。

## 事件线（`events.md`）—— 跨章的主线 / 感情 / 反派

```markdown
## 主线：远离与反扑
- 目标：让她自己走到「求他」那一步
- 起点 → 终点：第 1 章 → 第 100 章

### 主线-1 真相落地（1–3）
- 因为：她亲眼看到离婚协议上的日期早于他说的「昨天」。
- 所以：她第一次主动找他核对时间线。
- 不可替代：换成别的理由，就没人会去翻那份协议。
```

- 二级标题 = 一条事件线（`## 主线：名字`、`## 感情：名字`、`## 反派：名字`），三级标题 = 这条线上的一个事件，`（起–止）` 是覆盖的章区间。
- 一个事件必须写清 `因为` / `所以` / `不可替代` —— **「不可替代」写不出来，这个事件就不该存在**（能换成别的理由推动，说明它不是主线）。
- 用 `novel_events({ line, content })` 整段替换一条线，不要手改文件；无参调用看全书事件线与推进情况。

**章纲里锚定事件（一章可以推好几条线）**

```markdown
## 0001 第一章

- 事件：主线-1、感情-1
- 场景：…
```

- 区间只是默认值：落在 `（起–止）` 里就算推进；写了 `- 事件：` 就是锚点，可提前、可推后、可跨线。
- 一章推 4 条以上就会散（`novel_check`/泳道会提醒）；一章一条主线 + 一条感情线是正常密度。
- 落在区间里却没锚，等于右栏泳道和装配包都以为这章不推线 → `novel_check` 报 `spine-unanchored`；锚了但超出区间报 `spine-conflict`。

## 伏笔表

```markdown
| 伏笔 | 埋设 | 回收 | 状态 |
| --- | --- | --- | --- |
| 投币箱里多出的那枚硬币 | 0001 | 0004 | open |
```

埋了就登记，用 `novel_threads({ thread, planted, payoff })`，不要手改表格。「回收」列写的是**计划**回收章，状态留空 = `open`，真收掉了才写 `done`——到期（计划回收章 ≤ 已写到的最新章）却没写的，右栏会标「到期」。

## 写作流程（每章都走一遍）

> 开书那一次还要多做一步：把主线拆成事件线写进 `events.md`（`novel_events`），并在每章章纲里用 `- 事件：` 锚好。没有事件线，写到第 30 章就会出现「主角在忙，但主线没动」。

**第 0 步：开书先立世界（只做一次，跳过它后面全是返工）**

在动笔写任何一章之前，先把世界观落成 `settings/` 里的条目，**至少 3 条、推荐 5–8 条**（地点 / 规矩 / 物品 / 术语 / 组织），每条一次 `novel_setting({ name, content })`，正文第一行必须是 `- 分类：…`。

- 世界规则、金手指的限制、社会规矩、行业黑话**必须落成设定条目**；
- 只写在 `outline.md` 里等于没写：outline 是给人看的散文，`settings/` 才是写正文时会自动装配进去的东西；
- 书名/题材/目标字数用 `novel_book`，那不算设定。

1. `novel_status` —— 现在写到哪、目标多少字、缺什么（设定 0 条时会当场提醒）
2. `novel_context({ chapter })` —— 拿「本章章纲 + 上一章结尾 + 出场人物卡 + 未回收伏笔 + 相关设定」的装配包
3. 按装配包写正文（1000 字左右一章，别一句话带过一个场景，也别把三章的事塞进一章）
4. `novel_write({ chapter, content })` —— 落盘（写到接近目标字数但章纲还有场景没写完时，不要硬塞成大纲扩写，传入 `carryOver: true` 自动顺延到下一章章纲）
5. **【交付前必执行】对话与心理去 AI 味洗稿**：向用户交付任何一章前，必须先调用 `novel_deai_pack({ chapter })` 提取本章**全部对话（含前后语境）、心理/体感段与对称金句**，逐条去除 AI 腔（禁止对手同句头接龙复读、禁止对称格言收尾、危急时短促抢话、保住人物卡「说话」口癖），用 `novel_write({ chapter, mode: "patch", ... })` 局部回写。
6. `novel_check({ chapter })` —— 自查（长度 / 重复句 / 半角标点 / 未登记的人名 / 旧称 / AI 腔默认开启）；如果出现 `style-drift` 或 `ai-tone`，**当场用** `novel_context({ chapter, mode: "rewrite", pass: "deai" })` 局部修正并再自查一次。
   - 为什么不能拖到下一章：实测一份 80 章的书，句均字数从 17 一路掉到 10.1、对话段占比从 26% 涨到 64.5%——**漂移是累积的**，越晚纠越费事，而且后写的章会照着前面已经歪掉的稿子继续歪。
   - `novel_write` 写完也会自动跑一次节奏比对，返回里有警告就别装没看见。
   - 右栏章节列表里挂了「漂」红标的章，就是节奏已经偏离文风卡的章。
7. 有新人物就 `novel_card`，有新设定就 `novel_setting`，有新伏笔就更新 `threads.md`

## 导入旧稿（已有的一整本 txt / 一堆 md）

不另设导入工具，按这个顺序用现有工具：

1. `novel_read({ source: 'D:\\路径\\旧稿.txt', limit: 4000 })` —— 自动认 UTF-8 / GBK / UTF-16，返回里带 `encoding`、`chars`、`nextOffset`。分批往下读，看清章节标题长什么样、有没有目录页。
2. **你自己判断章节边界**（插件不猜）：标题是哪一行、哪几行是目录、有没有缺章。
3. 逐章 `novel_write({ chapter, title, content, mode: 'replace' })` 落盘 —— 会自动留历史版本；章标题写进 `title`，不要写进文件名。
4. `novel_status` 核对：章数、总字数、有没有空章。
5. 需要再逆向提炼：`novel_outline`、`novel_card`、`novel_setting`、`novel_style({ clone: true, source })`。
   **长篇不要一口气读完**：每 8–10 章派一个 `subagent`，它只读原文、只返回「3 行摘要 + 出场人物 + 出现的专名/规矩」，由你汇总成大纲和卡片；子代理不许写文件。

## 红线

- **第一章开篇纪律**：前 300 字必须见冲突、异常或反常识奇观，禁止日常慢热或纯背景科普开局；即使主角表面吃亏，章末前也必须拿到实打实的筹码、信息优势或暗中收益，不写纯憋屈的第一章。
- 主线不许只写在 `outline.md` 的散文里：要落成 `events.md` 里**带因为 / 所以 / 不可替代**的事件。
- 一个事件跨好几章是正常的，别为了「一章一个事件」把它硬塞进一章。
- 爽点、钩子、信息行、事件锚点都写在章纲里，**不要另建资产文件**。

- **正文里不要出现 `## 关系` / `## 状态` / `## 0003 章纲` 这类结构标题**——那是卡片和章纲的格式，不是小说正文。
- 不要改动 `book.json` 的章节 id；新章节用 `novel_write` 或右栏「未写 +」建，不要手搓文件。
- 不确定的设定不要自己编；先问我，或者先在 `settings/` 里补一条再写。
- **世界规则不许只写在 `outline.md` 里**：金手指边界、社会规矩、地点规矩都要有 `settings/` 条目，否则写下一章时装配不到，前后必然打架。
- **`（待写）一句话梗概` 不是正文**：`novel_status` 会把这种章算成「占位」而不是「已写」。把梗概扩成真正的章节（1000 字上下，场景、动作、对话都要有），别拿梗概交差。
- 改别人已经定稿的段落之前先说一声。
- 写卡/写设定/写章纲之后，如果工具返回里出现「⚠ 格式提醒」，**要照着改一遍再往下写**：那说明刚才写的东西落盘了，但关系图/时间线读不到。

## 文风卡（`styles/<名字>.md`）

- 起卡：`novel_style({ source: "D:\\某本小说.txt" })`（或 `text: "…"`）先拿到量化结果和 5 段原文锚点；再把锚点抄进卡里，补上禁忌。中文 txt 会按 GB18030 兜底解码，32 MB 上限。
- 卡的骨架：

  ```
  # 文风卡：<名字>
  - 来源：<哪本书/哪些章>
  - 一句话：<这套句子的脾气>

  ## 节奏
  - 平均句长 12.7 字 / 平均段长 33 字 / 对话占 7%

  ## 锚点原文
  > 逐字抄 3–5 段，不要改写、不要概括

  ## 禁忌
  - 氤氲、缱绻、心中暗道、不由得
  - 大段心理独白
  ```

- **锚点原文是唯一真正起作用的部分**：写正文前先读它，句子长度、停顿、对话比例照着来；形容词式的「语言优美、富有张力」没有任何约束力。
- `## 禁忌` 中的禁用词、整句会被 `novel_check` 做字面检查，命中报 `style-banned` 并附行列位置。推荐一行一项，用 `禁用词：` 或 `整句：` 明确类型；`## 少用词` 仅提醒，`## 语义禁忌` 由会话 AI 复核，不按字符串判断违规。禁忌要写成**具体的词或句式**（「不由得」「仿佛」「他心中暗道」），不要写「不要太文学」。
- 启用/切换：`novel_style({ name, active: true })` 或右栏「小说文风」页点「用这套」；同时只有一套生效（`book.json` 的 `style`）。
- 写完一章后自己对照：这一章里有没有出现禁忌词？句子是不是明显比锚点长？如果偏了，改正文，不要改文风卡。
### 参考原文与「长样本」怎么办

- 卡里只放 3–5 段锚点；**原文另存一份**：`novel_style({ name: "<名字>", sample: "D:\\某本小说.txt" })` 会分析并把原文存成 `styles/<名字>.sample.md`。右栏「小说文风」页点「看原文」能回看，你也能随时读这个文件比对句子。
- 样本 **≤ 1.5 万字**：自己读、自己写卡，别开子代理，浪费。
- 样本 **> 1.5 万字**（整本长篇）：用 `subagent` 分块提炼，不要一口气硬读 ——
  1. 先 `novel_style({ name, sample })` 把原文存下来，拿到统计量和 5 段采样；
  2. 起 2–4 个子代理，每个只负责一段章号区间（例如 1–10 章），任务是：读 `styles/<名字>.sample.md` 里自己那段，返回「句法特征（句长/断句/段落长度）、用词偏好（列 10 个高频实词 + 3 个作者的坏习惯词）、对话怎么写、反复出现的意象、3 段逐字原文候选」；
  3. 汇总它们的结论，**只保留两三个子代理都提到的特征**，再把锚点原文抄进卡；
  4. `novel_style({ name, content, active: true })` 写入并启用。
- 子代理只读样本、不写卡：卡必须由主对话合成，否则四张卡会互相矛盾。
- 样本换了（换了参考书）就重做卡；不要在一张卡里混两本书的文风。
## 文风卡的结构（照着 templates/style-card.md 写）
- 自动克隆只给骨架：统计量、锚点原文、自动挑的禁忌词。
- **必须补的六节**：段落单位 / 短句是重音 / 具体的事 / 对话标签 / 旁白分寸 / 过渡断场。
- 没补规矩的卡，模型只能照着锚点模仿句子长度，学不到「怎么写才对」。
- 补完用 novel_style({ name, content }) 覆盖；禁忌里既能写词（氤氲），也能写整句（他拿起笔。）。

## 节奏与戏份：两个「承诺」的写法

- 大纲里写「三章一爽点」（或「每 3 章至少一次爽点」）：插件读这个数当断档阈值——状态条、章纲页红字、`novel_check` 都按它判，不是写死的 2。
- 人物卡里写 `- 戏份：每 8 章至少出场一次`：插件按正文统计 TA 的出场章，超期就在 `novel_check` 报 `absent-role`，人物页挂「欠场」徽标。
- 两行都没写 = 用默认（每 2 章一次爽点、不检查出场）。**规矩要落成这两行，模型才会被约束**，写在正文散文里没人查。
### 「- 心里：」章纲里的内心材料（每章 1–2 条）
- 场景是"他做了什么"，心里是"他想到什么"。只写场景，正文必然写成流水线。
- 写具体的东西：一个画面、一句话、一个数字（「想起他爸递二十块那一下」）。禁止写「他感到后悔」「心里很复杂」——概括会被原样抄成口水话。
- 位置不固定：别每场都写，也别固定放章末。固定位置 = 工业产物。
- 自查会报 `no-interior-plan`（整章章纲一条都没有）；`novel_write` 会报「章纲写了 N 条内心材料，正文里一段都没落到」。

## 章纲只写提词卡（标签，不是正文）
章纲越长，正文越平——写整句会让它变成第二份正文，还挤掉装配包预算。

- `- 场景：谁 → 在哪 → 想干什么 → 撞上什么 → 爽点（类型）`
- `- 心里：确认重生 / 算账 / 回忆 / 对比前世 / 发狠`（写主角，每章 1–2 条，紧跟那一场）
- `- 反应：反派尴尬 / 反派嘴硬 / 前妻维护 / 群众愣住 / 同伙互看`（**每场 1–3 条，分不同的人写**；打脸场必须至少一条，否则正文只剩主角动作）
- `- 信息：` 读者这一章必须知道的事（每晚 0–2 条）
- 落点、钩子各一行

判断标准：一条标签 AI 能扩成一段，就不要把那段写进章纲。

## 改写时的完整性约定

- `novel_context` 返回 `ready: false` 时，不得据此覆盖整章；先增大预算或使用 `rewriteStart` / `rewriteLimit` 获取片段。
- 默认先局部修订：`mode: "rewrite"` 获取范围后，用 `novel_write({mode:"patch",chapter,start,end,baseHash,content})` 保存；参数取自 `rewriteScope`，其余正文由插件保留。
- 保存后重新读取上下文，重新确定下一段范围，不直接复用旧索引或哈希。
- 全章改写必须拿到完整原文，保存时传 `baseHash`；先核对事实、动作、信息点全部保留，再检查文风。统计节奏偏差不自动意味着需要整章重写。

## 出场描写：第一次露面要交代

新人凭空说话最伤读者。章纲里给他一行：

``n- 场景：江野 → 教室门口 → 想直接走掉 → 撞上陆景明拦在门口 → 爽点（打脸）
- 出场：陆景明｜白衬衫、金丝眼镜，比同龄人高半个头，笑着递烟的样子像在替你着想
``

- 只在本章**第一次露面**时写；同章第二次出现不再写
- 一章最多 2–3 条，只在真有新人登场时
- 只写看得见的：衣着 / 体型 / 姿态 / 一个动作；身世性格交给人物卡
- 名字与描写用 ｜ 分隔，一句就够

## 时间线：生死用状态码，不写散文

人物卡里写：

```markdown
## 时间线
- @0001 已故｜死因：讨丹坠崖｜尸首：未寻回
- @0040 复活｜方式：被人在山里救起
```

- 状态码只有七个：`在世` `去世` `已故` `失踪` `假死` `复活` `远走`
- 行首必须是 `@章id 状态码`，后面用 `｜` 接字段（死因/地点/方式）
- `去世`＝书内死亡，`已故`＝开篇之前就死了——这两个界面标记不同，别混用
- **不要**写「死账」「死对头」「拼死」这类含「死」字的散文，也不要只写一个「死」字
- 不确定就写 `@0030 在世｜……`；不写状态码插件只能靠关键词猜，会误判
## 心里：要情绪，要台词，不要案情摘要

```markdown
- 心里：暗爽｜卧槽，穿越者的标配吧这是
- 心里：火｜这王八羔子，八十块也敢上门
- 心里：心凉｜人死了三天，账还热着
```

- 格式 `情绪｜台词`，用全角竖线隔开
- 情绪只取：暗爽 / 得意 / 憋屈 / 火 / 慌 / 心凉 / 发狠 / 松口气 / 不耐 / 恶心 / 钝痛 / 疑惑 / 心疼 / 讽刺
- 台词必须是**能直接抄进正文的口语**，带脏字也行；不要写成「他把规矩过了一遍」这种概述
- 每章 2–4 条，跟着情绪转折的那几场走
## 认知：这一章他此刻还不知道什么

穿越、失忆、新手、刚入行的角色，最容易写成"一开口就像本地老手"。章纲里给他一行：

```markdown
- 认知：第一次看见黑字，以为眼花；不知"系统"为何物
- 认知：认得坊市和三利号，那是原身的记忆
```

- 另起一行，写**边界**而不是身份（"他是穿越来的"是身份，"他不认识这屏字"才是边界）
- 一章 0–2 条，只在认知真的变了的时候写
- 装配包会单列「本章认知起点」，并提醒：不知道的别让角色装懂
