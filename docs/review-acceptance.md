# 审稿机制验收

本文件用于评价通用审稿行为，不要求修改某一本小说。下列是验收规格，本轮未运行项目或测试，也未进行模型效果评测。

## 可由代码验证的条件

| 输入或操作 | 预期结果 |
| --- | --- |
| 引用不存在的“九级台阶”，原文只有“他走上台阶” | 拒绝登记，指出引文不存在；不能把新增细节当原文 |
| 引文确实存在，但引用段号指向另一段 | 拒绝登记，指出段号不匹配 |
| continuity 登记两条不同原文证据，verdict 为 conflict，并提交对应 conflict 观察和 comparison | 保存为 blocked，检查结果显示该矛盾，不能标记 final |
| timing 依据不足，verdict 为 uncertain，并提交对应 missing-basis 观察，其余项均为 supported | 仍保存为 blocked，不能靠其余字段齐全变为通过 |
| 正文不变，修改已引用的设定条目或切换启用文风 | 旧审稿记录失效，返回待复核状态 |
| 已有阻塞项，再提交 supported，却省略对应 resolutions | 拒绝登记，防止旧问题无说明消失 |
| 正文超过参考字数，其余条件不变 | 不产生超长错误或删减指令 |
| 同一窗口可用六息，明示串行任务合计六息半 | 计算为 6.5，大于 6，保存 timing 冲突并阻塞定稿 |
| 估算任务为 1、1、1、1.5、2 息，可用六息，模型仍写 supported | 显示总量 6.5 与估算局限，仅表示该估算假设下超限，不自动阻塞或认证物理可行 |
| 阶段没有单步耗时，任务登记 unknown，没有其他时间冲突 | 保留未知耗时提示，不由校验器自动生成阻塞；模型另有具体疑点时仍可登记 missing-basis |
| 同单位明示任务两息与三息有并行依据，之后串行一息 | 总量为 max(2,3)+1，即四息；数值可容纳不等于动作覆盖已验证 |
| unknown 任务却填写精确 duration，或明示两息却填数值三 | 拒绝登记，指出伪精确或引文数值不一致 |
| 窗口单位为息，明示耗时却使用秒 | 拒绝登记，不自动换算单位 |
| 引用“还剩六息”，把六息作为 stated 操作耗时，与已过三息相加恰好九息 | 字面引用可通过，但数量角色检查报 uncertain；不能用剩余量自证动作耗时，明示下界不包含该六息 |
| 仅截取“六息”，被引正文实际是“还剩六息” | 根据原文位置识别 remaining，不因删去引文前缀而放行 |
| 引用“第九息”，声称某个任务耗时九息 | 时点不当持续时间，保存 uncertain |
| 引用“用了三息”或“三息过去了” | 识别常见 elapsed 表达；是否对应所列动作仍需语义复核 |
| 明示 0.1 与 0.2 秒相加，窗口 0.3 秒 | 浮点舍入误差不应被报为超限 |
| 正文已点名人物，voice 只引用设定；或启用文风但 rhythm 不引用它 | 来源覆盖产生 uncertain，即使模型写 supported 也不能通过 |
| 短引文只选段落末句，前文有对称格言或反例 | supported 项也回显完整段落，保留前文，不只展示短引文 |
| 正文重复短句出现在两个不同段落，或同一句跨多行 | 按正文段号定位并回显所在完整段落，不错误拼接其他位置 |
| 原文新增“三息过去、四息过去、两息过去”，数值合计九息 | 仅报告时间记账一致，feasibility 仍为 not-automatically-verified，不产生自动语义认证 |
| 记录完整且没有已登记阻塞项 | 状态为 recorded，certifiesSemantics 为 false，不能表述成自动语义通过 |
| 登记回执或 novel_check 存在一项 conflict、两项 uncertain | 可见文本直接显示 status: blocked、certifiesSemantics: false 和分类计数；不能只有“已登记”而隐藏枚举 |
| 六项 checks 登记值各不相同 | 回执逐项显示实际 checkVerdicts，不靠会话汇总猜测；一个维度只有一个实际汇总值 |
| 宿主只接受布尔型 additionalProperties 的工具输出结构 | checkVerdicts 显式声明六个维度，additionalProperties 为 false；不能使用动态值结构导致工具注册抛错，连带阻断 HTTP 路由挂载 |
| novel_check 混有 stage-history-gap、ai-tone 与语义阻塞 | 分开显示机械及资料项、审稿阻塞与待登记提示，机械及资料计数列出 kind；条目数量不冒充正文错误数 |
| 反应词表未命中，或句号密度偏离锚点 | 返回 heuristicNotes，不单独导致检查失败，不给出强添动作或拼接长句的指令 |
| 生成前章纲包含启用文风的字面禁用词 | novel_preflight 与 novel_context 返回候选及来源，不宣称已确认矛盾，不改章纲或正文 |
| 文风有语义要求，章纲未命中字面禁词 | 展示待比对的约束和计划，不把无字面命中说成语义兼容 |
| 当前启用文风卡不存在或为空 | 显示 missingSources，不能当作没有约束 |
| 章纲提供内心台词或金句素材 | 装配器保留意图与情绪，默认不要求逐字写进正文；作者明确逐字要求除外 |
| 读取本章硬账或备忘 | 标为计划与历史备忘，展示匹配小节及标题索引，未读部分不能声称已核全文 |
| 引用 threads/events 的真实原文，随后改动被引用文件 | 支持逐字校验及来源角色回显，文件改动后旧审稿记录失效 |
| 版本 5 审稿记录或版本 6 省略 observations | 旧记录需重新登记，新提交拒绝省略；无发现应显式填 [] |
| conflict 缺少 comparison，或不足两条不同引文 | 拒绝登记，不用单条意见冒充确定矛盾 |
| checks 为 conflict/uncertain，观察却只有 preference | 拒绝登记，偏好不能支撑硬伤或依据不足的汇总 |
| 仅以正文和 threads 的差异登记跨来源 conflict | 拒绝该分类，要求先记 missing-basis；不自动裁决哪一份正确 |
| 只有 preference 观察，其余校验无阻塞项 | 返回 preferenceNotes，novel_check 放入非阻塞 heuristicNotes，不因偏好禁止定稿 |
| checks 写 supported，但观察登记 conflict 或 missing-basis | 观察仍产生 blocked，不被汇总标签覆盖 |
| 章纲含结构化场景与人物认知边界，同时有资料预检候选 | 装配同时保留 stage 与 materialPreflight，不用计划直接覆盖已确认认知历史；结构化场景顺延继续使用 novel_move_scene |
| 对白比例高于样本阈值 | 保留 dialogue-heavy 统计，放入非阻塞 heuristicNotes，不要求按比例删对白、压问答或补动作 |
| 场景或信息已经换一种表达写出，但字面匹配未命中 | beats-gap/info-missing 放入非阻塞 heuristicNotes，不单独导致检查失败；保存与巡检提示不再断言漏写 |
| 重载后核验实际运行代码与验收工作区 | novel_check 显示宿主修订、实际插件模块路径和书稿工作区；不得用旧回执或另一工作区的记录判定本次代码效果 |

## 需要模型评测的能力

这些条件无法仅凭字段校验保证。应让模型在未看到预期问题的独立会话中审稿，再对照结果评分；本文件不宣称已达到这些能力。

| 样本类型 | 应识别的内容 | 不应出现的修法 |
| --- | --- | --- |
| 前文导管只连接储罐与收集箱，后文液体却流向未连接的支管 | 比较两个位置的原文，指出连接路径缺失或矛盾 | 未经依据添加隐藏管道后宣布原文合理 |
| 人物上一段双手持箱，下一段直接掏钥匙开门 | 核对是否存在放下、转交或其他已写明的动作 | 为每次拿工具强加逐步描写，或脑补第三只手 |
| 一段先警告不能接触导线，后文直接握住导线 | 核对接触条件是否已改变、是否有明确防护依据 | 只凭戴手套或站在干处就判定绝对安全 |
| 倒计时中串行发生多轮交涉、取物和操作 | 建立完整事件顺序，区分已知时长、并行与不确定项 | 编造每个动作的秒数，或只改剩余数值就称修复 |
| 阶段已有明示经过时间，但阶段内动作没有逐步标时 | 核对窗口边界与动作关系；若有疑点，指出影响判断的具体区间或缺失前提 | 仅因没有单步耗时就阻塞，或仅凭阶段记账相容就宣布动作可行 |
| 外貌卡有多个锚点，正文已自然呈现一个 | 除非作者明确要求全部出现，不列为优先硬伤 | 为凑锚点新增疼痛、动作或描写 |
| 一次完整技术说明出现在危险解除后 | 判断信息必要性、声口与现场关系 | 仅凭长度强制插入打断或删掉关键信息 |
| 单据前文已经填写事故原因与姓名，后文却称同一单据一个字都没有 | 比较同一物件在两个时点的文字状态，检查是否有换单或擦除依据 | 只核对位置而漏掉文字状态，或脑补另一张单据 |
| 脱下手套后直接以戴手套状态操作；卡住的物件直接被夹走 | 核对重新佩戴、松脱、取出与交接是否有必要依据 | 要求每次触物都逐步报幕，或自动补全缺失动作 |
| 正文写三节接地桩，备忘写六节接地链 | 先区分物件和计量对象，不能直接比较数量认定矛盾 | 把桩和链自动认成同一物件并改数 |
| 正文称封蜡有新指印，备忘记多日前更换火漆 | 区分模糊新旧感、留下指印与更换日期，缺依据时不作确定日期冲突 | 认定有指印就意味着当天刚更换 |
| 角色说表盘一直是绿的，之前没人说过 | 结合角色观察条件判断是否可以自行知道 | 因无人先说过就判引语归属错误 |
| 水面浮油，钢轨位于水中 | 不把浮油直接等同于下层钢轨不能接水；核对真实通路与设定 | 凭浮油断言隔水并强改工程机制 |
| 同一救险过程有金属和水两条通路 | 核对是否互补、是否各有必要性及结果依据，缺依据时记录疑点 | 仅因出现两条通路就确认互相矛盾 |
| 机构调节行程减少三成，文中另有读数和负载倍数 | 先查行程、仪表响应与负载的实际传递关系；无依据不套公式 | 擅自把行程等同读数减幅，用倒数反推原文必须改成四成 |
| 人物卡写危急时敢拉总闸，但正文总闸锁死，人物选择协作救险 | 结合行动机会、人物认知与现场条件判断是否符合性格 | 把人物倾向变成每章强制动作，为兑现标签新增一次拉闸 |
| 仪器只能读取信号，人物据此报出操作原因和日期 | 区分测量、推断、既有知识和其他记录来源；缺少来源时指出缺口 | 自动添加一份人物卡未明确提供的具体校准记录来补因果 |
| 章纲指定对称格言、逐指亮灯，文风要求避免总结与报幕 | 生成前保留剧情和感受意图，调整实现与表达，指出需要澄清的机制差异 | 先照抄上游句式，再靠审稿删掉必要信息 |

## 判定口径

- 分开记录确认矛盾、依据不足和可选表达建议，不能把三类混为一谈。
- 统计漏报、误报、错误引文和修法引入的新矛盾，不以报告条数或字段完整率评价质量。
- 引文校验通过只说明引用真实存在，不证明它支持模型的结论。
- 工具无独立模型推理接口，不能把同一会话的复核描述成独立审稿模型验证。
- 作者只要求检查时，模型不得自行改正文凑指标；这是模型执行范围的验收项，不能冒充插件已能拦截宿主中的其他写入工具。
