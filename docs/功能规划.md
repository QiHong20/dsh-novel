> 这份文档是**施工图的唯一真相**。写代码前先读它，写完更新勾选框。
> 判断一个新想法要不要做，只看两件事：✅ 属于本文「定位」范围内的增量，❌ 不触碰「反目标」。
> 与 `design.md` 的关系：design.md 是最初的切面草案（保留作决策考古），本文是定稿路线图。

## 一、定位（一句话）

**一个工作区 = 一本书。** 插件不存正文，只给「工作区里那堆 Markdown」加上**结构、连续性、接续、节奏**四样不装就没有的东西。

### 为什么需要它（不装插件缺什么）

| 缺口 | 不装插件时的样子 | 插件给的增量 |
|---|---|---|
| 结构 | 一堆 `第一章.md`，谁在第几章、写了多少字、哪章没写全靠脑子 | 章节有序清单 + 进度 + 字数 |
| 连续性 | 写到第 87 章，第 3 章的伏笔早被上下文挤掉了 | 资料库（人物/设定/伏笔）按需装配进上下文 |
| 接续 | 每次续写都要重新交代「上章结尾是什么」「主角叫什么」 | 一条命令拿到装配包：上章结尾 + 出场人物卡 + 本章大纲 |
| 节奏 | 一章 3000 字还是一章 800 字，全凭手感 | 每章字数/对话比的反馈，写的时候就知道偏了 |

### 成功判据

> 作者能在**三步之内**完成「接着写下一章」，且模型不把主要人物写错名、不推翻已定设定。

## 二、反目标（明确不做，防止跑偏）

1. **不做书库应用**：不建第二个存储、不把正文搬进数据库、不做「导入/导出同步」。正文永远是工作区里的 `.md`。
2. **不接管编辑器**：不做富文本/所见即所得正文编辑器（重版视图 v0.3 之后才考虑，且只做「看 + 定位」）。
3. **不做多作品书架**：一个工作区一本书。多书 = 多工作区，左栏本来就是书架。
4. **零运行时依赖**：`package.json` 不加 `dependencies`。客户端 bundle 里只能 `require('react')`。
5. **不写兼容闸门**：不声明 `engines.dsh` / `dsh.compatibility.dsh`（会挡住 link: 安装）。
6. **不自动生成整本**：插件是「助手」，不是「一键出书」。所有写操作必须由作者或对话显式触发。
7. **不破坏用户文件**：不重命名、不移动、不删除正文；`replace` 必须显式传参，默认 `append`。

## 三、数据契约（跨版本不能随便改）

### 目录布局

```
<工作区>/
  book.json              ← 书的元数据与章节清单（真相源）
  outline.md             ← 大纲（作者可手改）
  beats.md               ← 章纲（v0.2 起：每章一节 `## <章 id> <标题>`，场景清单）
  threads.md             ← v0.2 起：伏笔表（人工清单，表格）
  characters/            ← v0.2 起：人物卡，一人一文件
  settings/              ← v0.3 起：世界观设定，一条目一文件
  styles/                ← v0.3 起：文风卡，一套一文件（book.json 的 style 指向在用那套）
  chapters/
    0001.md
    0002.md
```

### `book.json`

```json
{
  "version": 1,
  "title": "雾港旧事",
  "author": "试写",
  "genre": "悬疑",
  "summary": "一句话简介",
  "targetChars": 3000,
  "chapters": [
    { "id": "0001", "title": "第一章 起雾", "file": "chapters/0001.md", "status": "final", "targetChars": 4000 },
    { "id": "0002", "title": "第二章 账册", "file": "chapters/0002.md", "status": "draft" },
    { "id": "0003", "title": "第三章 空铺", "file": "chapters/0003.md", "status": "planned" }
  ]
}
```

规则：

- **章节顺序 = `chapters` 数组顺序**（不是文件名字典序，方便插章、调整卷序）。
- `book.json` 不存在时：回退扫描 `chapters/` 目录，按文件名排序生成临时清单（只读场景可用）。
- `id` 是 4 位递增字符串（`0001`…），一旦分配**永不复用**；章节标题改了 `id` 不变。
- `file` 一律存 **posix 相对路径**（`chapters/0001.md`），换平台不炸。
- `status`：`planned`（有计划没正文）/ `draft`（有正文未定稿）/ `final`（定稿）。
- `targetChars`：**章节目标字数**，缺省继承书的 `targetChars`（缺省 3000，合法区间 200–50000）；书级与章级都可写，章级优先。
- 未知字段原样保留（写回时 spread 旧 JSON），作者手加的注释性字段不会被插件吃掉。
- 字数口径：**去掉所有空白字符后的字符数**（中文场景下最接近「稿费字数」的直觉）。

### `threads.md`（伏笔表）

Markdown 表格，四条列：`伏笔 | 埋设 | 回收 | 状态`。

```markdown
| 伏笔 | 埋设 | 回收 | 状态 |
| --- | --- | --- | --- |
| 父亲的怀表锁在抽屉最下层 | 0001 | | open |
| 黑伞女人没喝那杯茶 | 0002 | 0004 | open |
| 铺子只在雾天开门 | 0001 | 0001 | closed |
```

- 表头与分隔行自动跳过；**状态留空 = `open`**（「回收」列是**计划**回收章，不是已收）。
- `open = status !== 'closed' && status !== 'done'`。
- 「到期还没收」：`due = open && 回收章非空 && 回收章 ≤ 已写到的最新章`。这条以前判不出来，因为旧规则把「有回收章」当成已收。
- `novel_context` 只挑 `open` 且（无预定回收章 或 回收章 ≥ 当前章）的伏笔，最多 10 条。
- 写入走 `novel_threads({ thread, planted?, payoff?, status? })` 或 `POST /novel-api/thread`：按第一格「伏笔」名匹配覆盖，找不到就追加；模板里的空占位行（`|  |  |  |  |`）会被清掉。
- 未知字段一律保留（作者手写的备注不能被插件吃掉）。

### `beats.md`（章纲）

**大纲管整本书怎么走，章纲管这一章拍哪几个场景。** 一个文件，每章一节，二级标题写成 `## <章 id> <标题>`：

```markdown
# 章纲

## 0003 第三章 空铺

- 开场：铺子空了三天，林小满第一次自己开门，柜台上一层薄灰
- 中段：账册自己翻到最后一页，那一页只有一个名字，字迹是父亲的
- 收尾：雾从门缝里渗进来，有人在门外喊了一声「小满」
```

- 解析只认二级标题：标题里的 4 位数字是章 id，标题其余部分是章名（章 id 匹配优先，其次标题包含匹配）。
- 写回**只替换这一章那一节**，别的章一个字不动；没有这一节就追加到文件末尾。
- `novel_context` 有本章章纲时优先给章纲（占预算 40%，最多 1200 字），大纲退成「背景参考」；没有章纲才回落到大纲里这一章的段落。
- 章纲缺失不是错误：`novel_status` 与右栏只报「章纲覆盖 N/M 章」，不拦着写正文。

**节奏标记（爽点 / 钩子 / 转折）—— 写在场景末尾，不另建表**

```markdown
- 场景：江野 → 把批条推过去 → 柜员脸色变了 → 爽点（信息压制）
- 落点：出门时有人叫住他。钩子：王厂长在车里等着。
```

- 两种写法都解析：`→ 爽点（类型）`（推荐）和既有习惯的 `钩子：…`（标记+冒号，冒号后当备注）。
- **为什么不做「爽点资产表」**：爽点只有一个端点（发生在哪一场），是场景属性；独立表必然出现「表里写了第 7 章打脸、章纲第 7 章没这场」的双份真相，而且 `novel_context` 装配的是章纲，表在写作路径上看不见。
- 归属规则：一对一属性跟对象走（生死 → 人物卡 `## 状态`）；跨对象且有生命周期才配独立表（伏笔 `threads.md`）；全书级稀疏锚点放 outline（`## 节拍`、`## 爽点节奏` 的预算 `打脸×3`）。
- 台账由宿主 `beatRhythm(root, chapters)` **现算不存盘**：`payoff / withPayoff / withBeats / hooks / turns / longestGap / currentGap`，`snapshot().rhythm`（含 `perChapter`）与 `GET /novel-api/beats` 的 `rhythm` 都来自它；预算用 `payoffBudget(outline)` 解析 `## 爽点节奏` 的 `×N`。
- `novel_check` 两条新规则：`no-payoff`（这一章一场爽点都没有，带上「已连续 N 章没有」）、`no-hook`（章末没有钩子）；`novel_context` 的装配包会插一段 `## 节奏（这一章怎么给读者回报）`。
- 断档只算「已经写了章纲」的章：没有章纲的章算未规划，不算断档。

**信息行（`- 信息：…`）—— 记录「这一章读者必须新知道什么」，但它不是场景**

```markdown
- 场景：江野 → 教室后窗 → 想确认这是哪一年 → 撞上前黑板报上「迎接新世纪」。 → 爽点（信息压制）
- 信息：现在是 1998 年 9 月，他回到了十六岁
- 信息：三天后厂里会出事
```

- **边界判据**：能被摄影师拍出来的（有地点、有对手、结束时状态变了）才写成 `- 场景：`；只在人物脑子里发生的（回忆、推断、前情交待）写成 `- 信息：`。**回忆一律不占场景位**，它是某个场景的写法（挂在「撞上什么」里），整章都在前世时才例外。
- 解析：`/^\s*[-*+]?\s*信息\s*[：:]\s*(.+)$/u`，只认行首，一条一行；`parseBeatInfos` 返回 `[{index, text}]`，`readBeats().section.infos` 透传给工具与 `/novel-api/beats`。
- **场景计数只数 `- 场景：` 行**（`beatCoverage` 的 `scenes.length ? scenes : rawLines`）：有显式场景行时，`落点/钩子/信息/备注` 都不算场次；老散文式章纲没有 `- 场景：` 时退回「所有非标记行」。
- 装配包单列一段 `## 本章要交付的信息（读者读完这一章必须知道这些）`，位置在章纲之后、节奏之前。
- 三条校验，都只提醒不改稿：
  - `novel_write` 写完后查「信息是否真的落地」（复用 `beatCoverage` 的引号术语/最长公共子串判据），漏了报「章纲里标了 N 条信息，有 M 条在正文里没落地」。
  - `novel_check` 的 `info-missing` 同上；`too-many-infos`（一章 >3 条 → 「再多就是在写提纲」）；`info-only`（有信息行、一场场景都没有 → 结构错误，逼着补场景）。
- **为什么要防这些**：信息行是「结果」，场景是「过程」。只写信息行，模型会把章纲当提纲写说明文；一章塞五六条，读者记住 0 条。

| `novel_book` | `{ title?, author?, genre?, summary?, targetChars? }` 改书元信息；`targetChars` 是全书默认目标字数 |

### `events.md`（事件线：主线 / 感情 / 反派，多路并行）

格式：

```markdown
## 主线：远离与反扑
- 目标：让她自己走到「求他」那一步
- 起点 → 终点：第 1 章 → 第 100 章

### 主线-1 真相落地（1–3）
- 因为：她亲眼看到离婚协议上的日期早于他说的「昨天」。
- 所以：她第一次主动找他核对时间线。
- 不可替代：换成别的理由，就没人会去翻那份协议。
```

- 二级标题一行 = 一条事件线（线 id 就是冒号前的名字）；三级标题 = 这条线上的一个事件，`（起–止）` 是它覆盖的章区间。
- 章纲里用 `- 事件：主线-1、感情-1` 锚定。**区间是默认值，锚点是修正**：落在区间里就算推进，锚点可以让它提前/推后/跨线。
- 一章可以同时推多条线（多对多）；一条线也能并行好几条（主线 / 感情 / 反派各一列）。
- 校验只警告不拒绝：锚了不存在的事件 id、锚点超出区间、一章推 ≥5 条线，各报一句。
- 三个视图：装配包「本章推进的事件」、自查（`spine-unanchored` / `spine-conflict`）、右栏「小说」一格里的「事件」分区 + 章纲页右缘泳道。
- **为什么不塞进大纲**：事件跨 3–8 章，写进每章章纲要抄八遍；一章塞完整因果链，模型会交「事件摘要」而不是场景。

### `settings/`（设定，与人物平级）

**人物管「谁」，设定管「这世界怎么运转」** —— 地点、规矩、物品、术语各一条，一个条目一个文件：

```markdown
- 分类：规矩

雾港的老规矩，进了门再收伞就是把雾气带进屋，主人家会有霉运。

- 收伞只能在门外，伞要立着靠墙，不能平放
- 雾天不点灯：灯亮着，雾里的人就知道屋里有人
```

- 文件名就是设定名（`settings/雾港的规矩.md`），第一行可选 `- 分类：地点`，右栏拿它当徽标。
- 摘要取第一条非标题、非「分类」行的文字，最多 60 字。
- `novel_context` 只在**正文/章纲/大纲里点名提到**这条设定时才装配它（最多 4 条、每条截 300 字），不会把整本世界观灌进上下文。
- 设定缺失不是错误：没有 `settings/` 目录时一切照常。

### `styles/`（文风卡，一套一文件）

```
styles/湖城夜行.md
  # 文风卡：湖城夜行
  - 来源：《first_novel》第 1–2 章
  - 一句话：夜里跑车的人，说话短，句子也短

  ## 节奏
  - 平均句长 12.7 字 / 平均段长 33 字 / 对话占 7%

  ## 锚点原文        ← 起作用的只有这一段
  > 「……」逐字抄三段到五段，别改写

  ## 禁忌
  - 氤氲、缱绻、心中暗道、不由得
  - 大段心理独白
```

- **形容词撑不起文风**：卡里真正起作用的是「3–5 段逐字锚点 + 明确禁忌」，其余是给人看的摘要。
- `book.json` 的 `style` 字段指向当前在用的那套；空表示不启用。
- `novel_context` 会装配文风卡（预算 30%，200–1200 字）段落标题为「本作文风（名字）」；`novel_check` 按 `## 禁忌` 逐条 `includes` 检查，命中报 `style-banned`。
- **参考原文单独留档**：`novel_style({ name: "湖城夜行", sample: "D:\path\某小说.txt" })` 分析之后会把原文存成 `styles/<名字>.sample.md`（卡里只放锚点，原文留在盘上，卸载插件也不丢）。右栏「小说文风」页点「看原文」读 `GET /novel-api/style-sample?name=`（只回前 6000 字）。
- 从一本现成的书起卡：`novel_style({ source: "D:\path\某小说.txt" })` 或 `novel_style({ text: "…" })` —— 返回句长/段长/对话占比/标点密度/高频双字词 + 均匀采样的 5 段原文，再把锚点与禁忌补成完整卡。中文 txt 会自动按 GB18030 兜底解码。
- **一条龙克隆（推荐，也是右栏「克隆文风」按钮走的同一条逻辑）**：`novel_style({ clone: true, source: "D:\path\某小说.txt", name: "可选名字" })` 一次做完——读原文（GB18030 兜底）→ `styleStats` 算节奏 → `sampleExcerpts` 切 5 段锚点 → 从 `CLICHE_WORDS` 里挑 8 个样本没用过的 AI 腔词当禁忌 → `composeStyleCard` 生成卡 → 写 `styles/<名字>.md` → 原文存 `styles/<名字>.sample.md` → 设为 `book.json` 的 `style`。返回 `mode: "clone"`，名字缺省用原文文件名。缺的只有「视角与时态」，读过锚点补一句再覆盖即可；HTTP 对应 `POST /novel-api/style-clone`。
- **锚点是连续窗口，不是「一个自然段」**：`sampleExcerpts` 从起点往后累积段落直到 `size`（默认 480 字，上限 16 段），因为短段落的书（这段样本一段才 30 字）只取一段等于只给了一句台词，学不到节奏。
- **长样本走子代理**：样本 > 1.5 万字（整本长篇）时不要一口气硬读，用 `subagent` 按章号区间切 2–4 路分别提炼（句法 / 用词 / 对话 / 意象 / 锚点候选），**只保留多路都提到的特征**再由主对话合成一张卡。子代理只读样本、不写卡 —— 否则几张卡互相矛盾。
- 卡缺失不是错误：没有 `styles/` 或 `book.json.style` 为空时，一切照常。
### 格式规范的三个落点（同一个约定写三遍）

模型不会读源码，它只知道工具描述和 `AGENTS.md`。所以「人物卡要怎么写」这件事必须落地三次，少一处就会出现「写了但读不到」：

1. **工具描述里给模板**（`novel_card` / `novel_setting` / `novel_beats` / `novel_write`）—— 写卡当时就能看到 `## 关系`、`## 状态`、`- 分类：` 的正确形状。
2. **书根 `AGENTS.md` 给全局规矩** —— 目录结构、六步写作流程、死亡词表、红线。DSH 自带 `@deepseek-ai/dsh-agent-instructions`（`dsh-base` 默认启用），会自动读工作区根的 `AGENTS.md`；新书从 `templates/AGENTS.md` 复制一份。
3. **写入时校验，只警告不拒绝** —— 四个写工具返回 `warnings: string[]`，在渲染里以 `⚠ 格式提醒（已写入，但下面这些位置读不到）` 列出。特点：
   - **不拦截写入**：作者想先堆草稿，不能让插件挡路。
   - **只报告"读不到"的东西**：关系小节里没有冒号的行、状态小节里没有 `@章id` 的行、设定首行不是 `- 分类：`、章纲里手写了 `## 数字` 标题、正文里混进 `## 关系` 结构性标题、空正文、场景数 0 或 >8。
   - **解析器顺手兜底**：`writeBeats` 会剥掉开头的 `## 0003 …`（否则文件里会变成两层标题）。

三条的关系：1 是「照着写」，2 是「知道总体规矩」，3 是「写歪了当场告诉你」。**别把 3 做成 400 错误** —— 那是把作者的草稿当敌人。

## 六、工具 API 契约（给模型看的门面）

| 工具 | 参数 | 返回 | 什么时候用 |
|---|---|---|---|
| `novel_status` | —（`root` 可覆盖） | `{ root, book, outline, chapters[], totals }` | 每次开写前确认「当前是哪本、写到哪」 |
| `novel_read` | `{ chapter: "0003" }` | `{ id, title, chars, content }` | 需要读某章全文（改稿、对前文） |
| `novel_write` | `{ content, chapter?, title?, mode?: 'append'\|'replace', status? }` | `{ id, title, file, chars, target, totalChars, created, status }` | 落盘正文；**默认 append**，新建章节时自动编号 |
| `novel_outline` | `{ content? }` | 有 `content` 则写入并回显字数；否则返回当前大纲 | 规划整本 / 查主线 |
| `novel_context` ✅ | `{ chapter?, budget?: number }` | `{ chapter:{id,title,target,status}, outline, prevTail, characters[], threads[], budgetUsed }` | **续写前的标准动作**，替代手工拼上下文 |
| `novel_card` ✅ | `{ name?, content? }` | 无 `name` = 清单；有 `name` = 读；再加 `content` = 写 | 维护人物/设定 |
| `novel_check` ✅ | `{ text?, chapter? }` | `{ ok, chars, target, issues: [{ kind, detail, count?, samples? }] }`；`kind ∈ stale-name / unregistered / repeated-sentence / punctuation / length / empty` | 写完自检、改名后查残留 |
| `novel_beats` ✅ | `{ chapter?, content? }` | `{ written, chapter, beats:{heading,text,chars,present}, coverage:{total,covered,missing}, sections[] }` | 不传参看章节覆盖；给 `chapter` 读这一章的拍摄清单；给 `content` 覆盖写（只动这一节） |
| `novel_events` ✅ | `{ line?, content? }` | `{ present, lines:[{id,name,goal,span,events:[{id,title,from,to,because,so,irreplaceable,chapters,written,total,status}]}], lineCount, eventCount, done, warnings[] }` | 无参看全书事件线与推进；给 `line` 读那条线；给 `line` + `content` 整段替换这一条线（别的线不动） |
| `novel_setting` ✅ | `{ name?, content? }` | `{ mode, settings[], content, chars }` | 无参列全部、给 name 读、给 name+content 写 `settings/<名字>.md`；`- 分类：地点` 一行决定徽标 |
| `novel_style` ✅ | `{ name?, content?, source?, text?, size?, active?, clone? }` | `{ mode, stats, excerpts[], styles[], warnings[], sample? }` | 无参列文风卡；**`clone: true` + `source`/`text` ＝一条龙克隆**（分析→写卡→存样本→启用，mode 为 `clone`）；给 `source`/`text` 只做分析（句长/段长/对话占比/标点密度/高频双字词 + 连续窗口锚点）；给 name+content 写卡；`active: true` 顺手启用 |

只写文件、不写正文的两个界面动作：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/novel-api/start-chapter` | `POST { id }`，须带 `x-novel-action: 1` | 把 `planned` 章节建出来（空文件 + 标题行），状态转 `draft`；幂等（`created: false` 表示文件已存在） |
| `/novel-api/outline` | `POST { content }`，须带 `x-novel-action: 1` | 覆盖写 `outline.md`（上限 256KB） |
| `/novel-api/beats` | `POST { chapter, content }`，须带 `x-novel-action: 1` | 覆盖写某一章的章纲小节，其余章节不动 |
| `/novel-api/event` | `POST { line, content }`，须带 `x-novel-action: 1` | 整段替换一条事件线（`## <线id>：<名字>` 到下一个二级标题），别的线不动 |

约定：

- 所有工具都接受可选 `root`，缺省走 `resolveRoot()`。
- 写操作返回**落盘事实**（路径、字数、是否新建），不返回「成功」这种空话。
- 报错要带可执行建议：如「`chapters/0003.md` 不存在，先 `novel_write` 建章或检查 `book.json`」。

## 八、技术红线（踩过的坑，别再踩）

1. 客户端 `exports.inject` **只认字符串数组** `['slots']`。对象写法 `{required, optional}` 会被当成服务名，插件永远 pending（v0.1 翻过车）。
2. 可选服务不要写进 `inject` 数组（会永久 pending），用 `ctx.inject(['sidebarRightTabs'], inner => ...)` 延迟订阅。
3. 右栏 `guide` 卡片的 `title` / `description` **必须是函数**（`entry.title()`、`entry.description?.()`）。
4. 客户端 bundle 不是 ESM：`window.__ModuleLoader__.load({ id, factory })`，`factory(require)` 只能命中平台基座。
5. 宿主侧不 import `@deepseek-ai/dsh-tools`（link: 装的插件解析不到宿主包）；`ctx.tools.register` 只认形状，手写等价对象即可，且**必须**有 `output.render`。
6. CSS 色值一律 `--dsw-alias-*`，用 `data-plugin` 标记归属，卸载要能回收。
7. `desktop` profile 被 App 独占，CLI 一律 `error: profile "desktop" is managed exclusively by the Electron application`；开发用 `--profile web`。
8. 端口被占先查是谁：`Get-NetTCPConnection -LocalPort 18080`；**54081 是桌面 App，别杀**。
9. 写接口只开十二个（`POST /novel-api/start-chapter`、`POST /novel-api/outline`、`POST /novel-api/beats`、`POST /novel-api/setting`、`POST /novel-api/thread`、`POST /novel-api/style`、`POST /novel-api/style-active`、`POST /novel-api/style-clone`、`POST /novel-api/style-delete`、`POST /novel-api/restore`、`POST /novel-api/event`），且**必须**要求 `x-novel-action: 1`：自定义头会强制 CORS 预检，跨站表单伪造不出来。新增写接口时照此办理，不要贪方便去掉这个头。
10. `/novel-api` 的路由在 `GET` 分支里穷举，新增路由要同时确认「非预期方法」返回 405 而不是 500。
11. 宿主里 `persistBook(root, meta, chapters)` 是顶层函数（早先嵌在 `apply` 里，被顶层 `startChapter` 调用时报 `persistBook is not defined`）。
12. 关系图的数据来自人物卡的 `## 关系` 小节，格式 `- 目标：说明`，目标名后可跟**起始章**标记 `@0007`（自第 7 章起；没有标记＝从开篇就成立）。**不要去解析自然语言**：格式固定才能可靠；目标没建卡时画成幽灵节点，比猜要诚实。
16. 关系的时间标记**只认起始章** `@NNNN`（四位章 id），不解析「后来」「三年后」这类自然语言时间；没有标记＝从开篇成立。**不记终点**（关系断了就改写或删掉那一行）。按章筛选时：`from` 晚于当前章的边不画的关系都不画。
17. **人物状态只认 @NNNN 起点**：人物卡里 ## 状态 小节写成 - @0003 去世（雾港码头） 表示「从第 3 章起进入这个状态，直到下一条状态为止」；没写这个小节＝一直活着。生死判定只看关键词表 去世|死亡|死|殁|阵亡|身亡|牺牲|遇难|丧命|死去|不在了，但**先剔除否定短语**（没死|未死|假死|装死|诈死|没去世…）再判，否则「其实没死」会被误判成死亡。**不要解析自然语言时间**（「三年后」「后来」），那不可靠。
18. **格式约定必须写在 AI 看得见的地方**：解析器（parseRelations / parseStates / parseBeatSections）只认固定格式，写错就**静默丢弃**——所以格式说明要在三处同时存在：①每个工具的 description 里内嵌格式模板（跟着调用走，最可靠）②书目录根的 AGENTS.md（DSH 的 dsh-agent-instructions 会把它当项目指令注入每次请求，预算 64KB）③插件仓库的 `templates/AGENTS.md`（新建书时拷一份）。**不要指望模型自己猜格式**。
19. **Markdown 渲染自己实现**（`MarkdownView` + `renderInline`，约 120 行）：DSH 没把官方 Markdown 渲染器（`ui-primitives` 的 `MarkdownText`）暴露给第三方 bundle，asar 里也没有 `ui-primitives` 包，`require` 不到；所以只支持标题 / 有序无序列表 / 粗斜体 / 行内码 / 引用 / 代码块 / 表格 / 分割线 / 链接，不追求 GFM 全集，不引第三方库。
13. 插件**没有**「替用户发送消息」的公开接口。能用的只有输入框动作面 `inputActions`（`captureInsertion()` / `insertText(text, span)` / `insertQuote(text)`），它以 props 形式传给 composer 区域的座位组件（官方 `dsh-experimental-client-ui-voice-input` 就是这么写回草稿的）。做法：在 `conversation.input.dock` 的状态条里抓住它存到模块变量，右栏按钮调 `insertText`；`insertText` 在草稿版本变化时返回 `false`，必须准备降级（复制到剪贴板）。**不要**尝试去调宿主的 `agent.followUp` / `sessionController.prompt`：那是宿主内部 API，插件解析不到 `@deepseek-ai/dsh-llm`，也拿不到 `createUserMessage`。

14. 章纲写回**只替换当前这一节的标题到下一个二级标题之间**，别的章一个字不动；`beats.md` 的二级标题是边界，所以章纲正文里不要再出现二级标题（三级及以下随便用）。
15. 「问 AI」的上下文必须截断：正文 1400 字 / 人物卡 1000 / 章纲 1400 / 大纲 1600，截断后缀统一写「…（已截断，原文 N 字）」，否则输入框会被塞爆

20. **格式校验只警告、不拒绝**：`novel_card` / `novel_setting` / `novel_beats` / `novel_write` 都返回 `warnings: string[]`（由 `validateCardContent` / `validateSettingContent` / `validateBeatsContent` / `validateChapterContent` 生成），render 里用 `warnText()` 渲染成「⚠ 格式提醒（已写入，但下面这些位置读不到）」。**绝不要把校验做成 400 拒绝** —— 草稿期写歪是常态，挡路比写歪更烦。另外 `writeBeats` 会剥掉开头的 `## 0003 …`，否则 `beats.md` 里会出现两层标题（已实测：不剥时 0002 那节会变成空标题 + 嵌套标题，覆盖率还算错）。

21. **`output.schema` 是硬闸门，不是注释**：DSH 会拿它逐条校验返回值，多一个没声明的字段就整条结果作废——报 `tool "novel_status" returned invalid output: "value.exists" is not a declared property (additionalProperties: false)`，`code: INVALID_TOOL_OUTPUT`，模型什么都拿不到，只能放弃工具去手写文件。所以：给返回值加字段时必须同步 schema，或干脆把根节点写成 `additionalProperties: true`（现在十个工具都放宽了）；对象字段不要用 `null` 占位（会报 `"value.beats" must be an object`），要么给对象，要么用条件展开省略。

22. **章纲要能验证，不能只靠模型自觉**：`beatCoverage(text, beatsText)` 逐条比对章纲的场次与正文（引号内术语出现，或最长公共子串 ≥ 8 字），`novel_check` 报 `beats-gap`、`novel_write` 写完后 push 警告。**依据**：first_novel 那本书就是「章纲 5 场、正文只落 3 场」却没人发现。

23. **手写的书也要能读**：没有 `book.json` 时按文件名解析章 id —— `/^(\d{1,4})\s*[-_.、:：]?\s*(.*)$/u`，`0003 第三章 湖心亭.md` → id `0003`、标题「第三章 湖心亭」。**依据**：工具坏掉那次，模型是用 `write` 直接落文件的，文件名带标题、没有 book.json，早先的扫描把整串文件名当成了 id，`findChapter('0001')` 永远找不到。
24. **「（待写）」占位必须和正文分开算**：`isPlaceholderText(text)`（首段以 `（待写/待补/待续/占位/TODO/TBD` 开头且全文 ≤300 字）为真时，`chapterStats` 给 `placeholder` + `written:false`，`totals.written` / `totals.planned` / 进度条都用 `written`，`novel_write` 不把状态转 `draft`，`novel_check` 只报一条 `[placeholder]`。**依据**：模型一次建了 50 章、每章一行梗概，界面却显示「已写 50 章 / 完成 2%」，字数与进度全在骗人。
25. **「当下用不到」的东西要主动喊**：设定条目最容易在写大纲阶段被降级成 `outline.md` 里的散文。所以 `novel_status` 固定输出「设定 N 条」，并在为 0 时给出「先建 3–8 条」；`novel_context` 在 `settings/` 为空时返回 `warnings` 并在装配包里印 `## ⚠ 动笔之前`。**依据**：真实会话里 `novel_setting` 一次都没被调用（其余工具 249/69/45/37 次），那本书的 `settings/` 至今是空的 —— 提示词约束不住，得让工具输出自己把缺口摆出来。

26. **爽点／钩子不建独立表，台账现算**：爽点只有一个端点（发生在哪一场），是场景属性；写成 `爽点.md` 必然和章纲变成双份真相，而且 `novel_context` 装配的是章纲，表在写作路径上看不见，模型不会照它写。做法：标记写在章纲场景末尾（`→ 爽点（类型）` / `→ 钩子` / `→ 转折`），台账由 `beatRhythm()` 每次现算、`snapshot().rhythm` 与 `GET /novel-api/beats` 输出，**不落任何文件**；预算（`## 爽点节奏` 里的 `打脸×3`）放在 outline，属于计划层。归属判断：一对一属性跟对象走、跨对象且有生命周期才配表（伏笔）、全书级稀疏锚点放 outline。
27. **不设 `novel_import`：导入是现有工具的编排，插件只补「编码 + 分页」**：`novel_read({ source })` 负责读任意外部文本（`detectEncoding`：BOM → 无 BOM UTF-16 → UTF-8 试探 → GB18030 兜底）并按字符 `offset`/`limit` 分页，返回 `encoding`/`chars`/`nextOffset`/`done`；**章节边界由 AI 判断，插件绝不猜**（猜错一次要重导整本）。落盘仍走 `novel_write`（自动留历史版本），逆向提炼仍走 `novel_outline`/`novel_card`/`novel_setting`/`novel_style({clone:true})`。**依据**：`read` 工具按 UTF-8 读 GBK txt 会出乱码，AI 只能现场写转码脚本、翻车后开始「猜原文」；而切章、建卡、提炼本来它就会做，再包一层只会多一套要长期维护的逻辑。
28. **章纲的边界：能拍的进场景，只有脑子里的进「信息行」**：`- 场景：` 一条必须同时有地点、对手、结束时状态改变；回忆/推断/前情一律不占场景位（写成某个场景的「撞上什么」，整章都在前世时才例外），需要让读者知道的事实写成 `- 信息：`。信息行是结果不是过程，所以**必须有护栏**：一章 >3 条报 `too-many-infos`；只有信息行没有场景行报 `info-only`（结构错误）；正文没落地报 `info-missing`（`novel_write` 与 `novel_check` 都会查，判据复用 `beatCoverage`）。**场景计数只数 `- 场景：` 行**，否则 `落点/钩子/信息` 会被当成场次，`beats-gap` 与覆盖率全部虚高（实测一章 3 场 + 1 钩子 + 2 信息曾被算成 4 场）。

29. **多对多的东西才配独立资产**：一对一属性跟对象走（生死 → 人物卡）、跨对象且有生命周期才配表（伏笔 `threads.md`）、一章推多条线是多对多（事件线 `events.md`）；全书级稀疏锚点（爽点预算）放大纲。判据写在前面，别到写代码时才吵。
30. **幂等锚点命中的补丁脚本要用函数式替换**：`text.replace(from, to)` 当 `to` 是字符串时会解释 `$&` `$'` 等模式 —— 注入的代码里只要有 `$'`，匹配点之后的整个文件会被复制一遍（实测把 16.6 万字膨到 29.4 万字）。一律写 `text.replace(from, () => to)`。

31. **`output.schema` 里声明成 `object` 的属性，任何分支都不许返回 `null`** —— DSH 会回 `value.line must be an object` 让整条工具结果作废，模型看到的是一条错误而不是「空」。空状态就用条件展开 `...(line ? { line } : {})` 把这个键整个省掉，别用 `null` 占位。同一个工具的不同分支（读 / 写 / 空文件）要一起过一遍 schema。
32. **「去 AI 味」采用机械线索与全文语义复核**——`novel_check` 默认开启线索检测，但不据此判定自然度；`novel_deai_pack` 返回全文、人物声口和文风卡，按时间压力、声口、叙述、节奏与事实五项审稿。多个修改用同一版坐标和哈希批量回写；最终版本由 `novel_deai_review` 记录逐段理由，正文变化即失效。新旧书的上下文均带最新流程；旧书规范可仅更新插件管理小节，保留作者自定义内容。
33. **改完工具就跑到 `tmp\check-all-schemas.mjs` 和 `tmp\check-write-schemas.mjs` 跑一遍**：它们用桩 ctx 把每个工具真调一次（读的那套 + 写的那套，写在临时副本上），按 DSH 的判据（类型 / `required` / `additionalProperties: false` 的未声明键）校验返回值。这一层能在用户遇到之前抓到 `INVALID_TOOL_OUTPUT`。
